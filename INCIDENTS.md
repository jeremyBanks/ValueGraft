## Critical recurring hazards

| Hazard | Observed failure | Current prevention |
|---|---|---|
| Wrong checkpoint/config | A “30B” run used a different/default model; thinking vs nonthinking checkpoint triggered false debugging | Print and independently attest exact model ID, revision, dtype, backend, geometry, parameter count before work |
| Kernel/schedule sensitivity | Identical long tokens under different query shapes shifted margins ~0.06--0.13 nat | Treat schedule as a condition; match primary calls; measure a production-path floor |
| Pseudoreplicated gate | Length variants of one periodic stream passed | Count independent literal contents; include an in-family fixture that fails for the intended reason |
| Invalid control text | Cycled filler and token-exact counterfactuals were incoherent | Blind complete-history review plus target-aware paired review before execution |
| Applied-dtype placebo failure | Float64 construction collapsed after bf16 casting | Demonstrate control availability on exact state geometry before treatment |
| Lost expensive render | Multi-hour rendering lived only in memory and died at timeout | Atomic per-case checkpoint before next case; pull/commit continuously |
| Host/runtime drift | Same Secure image exposed incompatible host drivers | Provider CUDA filter plus independent GPU/driver/memory/CUDA admission |
| Silent CPU/offload | Incompatible Torch silently loaded 30B on CPU | Fail unless CUDA is available and observed VRAM/model residency match |
| Broken detach/monitor | SSH stayed open; local nohup monitor died with its shell | Prove pipe EOF and child survival; use independent OS supervision |
| Liveness without progress | Alive runners waited or produced errors for hours | Monitor output rate, terminal counts, GPU memory, and last real artifact |
| Overwrite/collision | A model run overwrote another result | Unique model+UTC output path printed at process start |
| Apparatus spiral | Many amendments optimized gates while N stayed one | Every new gate names the decision-bearing threat; validation has a frozen attempt bound |

## Rules when an anomaly appears

1. Preserve raw bytes and classify KNOWN versus THEORY.
2. Verify the literal number, model, input, and output count before interpreting
   a status label.
3. If two independent apparatuses fail identically, inspect shared code/input
   first.
4. One or two failed fixes trigger an independent other-family review; do not
   grind.
5. Contaminated/void artifacts move to a named quarantine path and remain
   committed.
6. Never repair a scientific rule after seeing the outcome it governs. Create a
   new additive study or report the failure.

No legacy incident alone voids a successor result. Reclassification requires a
literal connection to the successor’s code, input, runtime, or analysis.
