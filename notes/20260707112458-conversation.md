The user identified the assistant’s unprincipled handling of its own JSON

The biggest conceptual correction in the shard came when the user realized the
J-lens document still lacked actual intervention evidence. The assistant had
been comparing only two states: old/write-time vs fresh-compacted. The user
pointed out that this does not show the effect of ValueGraft itself. After
initial resistance/misframing, `gpt-5.5` finally recognized the substantive
flaw: old-vs-fresh is merely a missing-state diagnostic, not intervention
evaluation. For studying the graft, at least three substantive conditions are
needed: full/write-time, fresh compacted, and grafted compacted; an `alpha=0`
machinery control is also useful. Reading `boundary_probe.py` revealed that a
grafted path had been attempted previously but the saved artifact contained only
`write_time_summary` and `fresh_compacted_summary`; `grafted_post_token` was
absent because the cache handling path had failed. The assistant explicitly
admitted having written a whole document around a failed graft path.

Fixing that became the next technical focus. The assistant patched
`boundary_probe.py` so the probe would operate post-boundary, where grafted
cache edits can matter, rather than only on summary tokens. It replaced an
optional `grafted_post_token` smoke path with a real `post_boundary_probe`
block: `full_context`, `fresh_compacted`, and `grafted_compacted` all answer the
same appended user probe; fresh/grafted are forced on the same first token
chosen from the full-context argmax; next-token candidates are recorded per
condition. There were also model/cache representation problems. Initial
assumptions about standard `.keys/.values` caches were insufficient. `gpt-5.5`
added support for both Qwen3-Next-style list caches (`key_cache` /
`value_cache`) and hybrid `DynamicCache` layer representations in Transformers
5.13, including preserving linear-attention conv/recurrent state. It changed
snapshot/rebuild logic to treat each layer as a structured record and to rebuild
caches faithfully before applying V-grafts. The assistant also corrected the
demo setup so the summary remained an internal compaction operation rather than
a user-visible turn.

A corrected `rivermark` intervention probe was eventually obtained after several
rounds of debugging. Acceptance gates from an independent audit were: the
artifact must actually contain graft data (`graft.available: true`) and include
`post_boundary_probe`; optionally, an `alpha-0` control should be present to
prove the machinery is inert when it should be. After hybrid cache fixes and

had a real grafted intervention state, an alpha-0 sanity control, and provenance

The assistant hardened the validator further: removed a `zip(strict=True)`
dependency, required forced-text alignment, and checked alpha-0 score equality
as well as token IDs.

This corrected intervention artifact led to a new report, replacing the earlier
invalid framing. The terminology also changed: “three-state” was recognized as
confusing because the artifact had three substantive states plus an alpha-0
machinery control, so the report and worklog were updated to use “four-sequence”
language. The new report was supposed to emphasize that the broad old-vs-fresh
sweep is diagnostic background only, while the corrected intervention probe is
the actual graft evidence. One concrete result highlighted by the assistant was
narrow but real: alpha-0 matched fresh exactly; aligned value graft with
`alpha_V = 0.75` changed 16 value-cache layers across 96 aligned positions and

aligned `alpha=0.75` and shifted control could both yield one argmax rescue, but
not the same one; importantly, shifted control worsened layer-48 closure while
aligned `0.75` improved it. This became an argument that local argmax rescues
alone are not enough; alignment-sensitive closure matters.
