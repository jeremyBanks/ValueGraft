# Methodology and implementation audit

**Author:** Sol — OpenAI Codex, GPT-5 family, extra-high reasoning  
**Attribution note:** The owner referred to this session as “GPT-5.6 Sol”; the runtime exposed GPT-5-family identity but not a verifiable minor version.

**Audit snapshot:** 2026-07-10. This is a read-only audit of the repository state visible during the review. I did not run GPU experiments or modify the tracked repository. Because another agent was actively changing the repository, artifact names and line references identify the snapshot I inspected.

## Executive verdict

The repository does **not yet establish a robust positive ValueGraft effect**. The strongest clean result I found is a reasonably well-controlled pilot null for one specific estimand: Qwen3-30B bf16 teacher-forcing foreign, pre-rendered synthetic conversations; generating its own realistic summary; grafting old values into both summary and retained-tail positions; and measuring authored-target log likelihood. That result excludes a large average benefit, but its 18-conversation confidence intervals remain wide enough to permit a small practically useful effect.

Several broader claims are not currently supported:

1. The compression-severity sweep does not reconstruct the intended generation-time cache for three of four summary levels. It generates with a level-specific request, then rebuilds the supposed write-time snapshot with the constant realistic request. Only the realistic level is prompt-consistent.
2. The definitive held-out experiment is described as using Qwen-native conversation replies, but its saved checkpoints show that the replies came from Qwen3-4B-4bit or external authors. Qwen3-30B bf16 only prefills that foreign text and generates the summary.
3. The implemented graft covers **summary and retained-tail tokens**, not summary tokens alone. It therefore cannot isolate a summary-state mechanism.
4. The shuffled/Gaussian placebo is not matched to the norm or covariance of the treatment perturbation. Consequently, `E - placebo` does not by itself establish content-specific information; it may show only that a near-identity aligned perturbation is less destructive than a much larger mismatched one.
5. The first SWE-Gym scalar positive did not replicate on the independent 98-trajectory pool. The new in-domain tuned map is positive on its internal disjoint 57-example evaluation set, but it is exploratory and awaits the untouched external confirmation described in the latest state note.
6. The SWE-Gym harness saves the generated summary text only indirectly, if at all, in the working output context: the result JSON records summary token count and arm scores, not the exact summary text, input context, target text/token IDs, or a full reproducibility render. Its manifest also lacks a dataset-content hash. This is not sufficient to reproduce the intervention after model/library nondeterminism or dataset drift.

The project nonetheless contains several unusually good practices: conversation-cluster bootstrapping, alpha-zero and identity checks, live-change checks, forced cache-type/shape checks, atomic checkpoint writes, explicit quarantining, retained raw artifacts, exact model revision and dtype in many manifests, and an admirably candid incident record. The main problem is no longer the absence of controls. It is that the prose claims outrun the exact estimand, some key controls are not causally diagnostic, and provenance in the final artifacts is incomplete.

## What the main held-out experiment actually tested

The cleanest description supported by the code and artifacts is:

> A bf16 Qwen3-30B model teacher-forced synthetic conversations whose assistant turns were generated by another model or authored externally; Qwen3-30B then generated a summary. On a fresh full prefill, selected value vectors from the old-conversation pass were mixed into positions corresponding to both the summary and retained tail. The primary outcome was mean token log probability of an authored gold string after several probes.

That is a legitimate causal cache-perturbation experiment. It is **not** the same as preserving a serving model's own generation-time values across its own compaction boundary. It also is not a direct behavioral task-success experiment.

The held-out realistic-summary artifact I inspected reports, across 18 conversations and 203 planted facts:

| Preselected configuration | Mean `E-B` | Conversation-cluster 95% CI |
|---|---:|---:|
| heads | +0.017 | [-0.027, +0.062] |
| layers | -0.0026 | [-0.0408, +0.0427] |
| intersection | +0.0079 | [-0.0316, +0.0525] |
| union | -0.0117 | [-0.0534, +0.0338] |

These estimates do not support a positive average effect. They also do not establish practical equivalence near zero without a predeclared smallest effect size of interest and a substantially larger sample.

## Critical findings

### 1. Fatal for the compression-sweep interpretation: the reconstructed write-time prompt is wrong

**Observed.** In `src/cross_arch_probe.py`, `summary_token_layout(...)` reconstructs `old_ids` using the constant `SUMMARY_REQUEST` (approximately lines 1291-1363). The experiment separately resolves a level-specific `_REQ` for ultra/brief/medium/realistic summaries (around line 1891), and generates the summary using `_REQ` (around lines 2492-2493 and 2722-2723). `build_token_context(...)` does not receive `_REQ`; it calls the layout helper that uses the constant request (around lines 1366-1388).

**Implication.** For ultra, brief, and medium levels, the text generated after one prompt is teacher-forced after a different prompt when the supposed generation-time cache is reconstructed. The values being grafted are therefore not the values that existed when that summary was generated. Only the realistic level uses the same request in both places.

**Inference.** The reported lack of dose response across compression levels is not a valid test of the intended write-time-state intervention. It may still describe a prompt-mismatched teacher-forcing perturbation, but it cannot support the paper's compression-severity conclusion.

**Required repair.** Persist exact generated summary token IDs and the complete generation prefix at generation time. Reuse those exact IDs and prefix when producing the old cache; never decode, strip, and retokenize. Add an assertion that the reconstructed prefix is byte-for-byte/token-for-token identical to the generation prefix and that every grafted vector comes from that pass. Rerun all non-realistic levels.

### 2. Fatal for model-native provenance: the held-out conversations are foreign renders

**Observed.** The validation jobs deliberately set `SC_NATIVE_RENDER=0`, as documented in `notes/2026070926-champion-validation-experiment.md` around lines 273-281. The `headscan_30b_bf16_*shuffle_pos*.json` artifacts record `native_render: false`. Their referenced render checkpoints identify Qwen3-4B-4bit for c01-c12 and external authors such as Sonnet for later conversations; many early replies were truncated. The treatment model is Qwen3-30B bf16.

**Observed conflict.** The current README describes the assistant replies as generated in context by Qwen3-30B and presents the held-out c07-c24 experiment under that provenance. That is not what the saved artifacts say.

**Implication.** The experiment measures state created by Qwen3-30B while *reading/teacher-forcing* another generator's text, not state from Qwen3-30B's own online generation. This matters because the project's own later evidence suggests self-generated summaries can behave differently from fixed/foreign summaries.

**Required repair.** Correct the paper and artifact inventory immediately. For the deployment estimand, regenerate model-native conversations with the exact production checkpoint, dtype, tokenizer, chat template, batching policy, and decoding configuration; save exact token IDs, text, and generation metadata. Treat the existing result as a foreign-render prefill result.

### 3. High: the graft is summary plus retained tail, not summary alone

**Observed.** The region builders in `src/cross_arch_probe.py` (approximately lines 1379-1382), `src/run_tune_hf.py` (approximately lines 120-126), and `src/run_swegym_hf.py` (approximately lines 397-404) construct aligned positions for both the generated summary and retained tail.

**Observed conflict.** The abstract/method language says values are replaced “at summary-token positions,” while a later alignment description mentions summary and tail.

**Implication.** No observed effect or null can be attributed specifically to summary-state retention. Tail-state transfer could help, hurt, or cancel the summary contribution.

**Required repair.** Report the intervention as summary+tail everywhere. Run a predeclared factorial comparison: summary only, tail only, both, and neither, with perturbation magnitude and slot count reported for each.

### 4. Fatal for the present “content-specificity” claim: the placebo is not treatment-magnitude matched

**Observed.** `src/cross_arch_probe.py` constructs Gaussian source values and normalizes them to the mean norm of source vectors, not to the per-position residual `delta = V_old - V_fresh` (approximately lines 383-410). Position shuffling likewise substitutes other source vectors rather than permuting and norm-matching the actual treatment deltas. The shuffle is not guaranteed to be a derangement.

**Observed result.** In the realistic per-layer condition, `E-placebo` is approximately +0.181 with CI [+0.091, +0.271], while `E-B` is approximately -0.023 with CI [-0.070, +0.033] and placebo-B is about -0.204.

**Inference.** A large `E-placebo` alongside a near-zero `E-B` is consistent with the placebo simply being a much larger and more destructive perturbation. “The right values beat shuffled values” does not yet distinguish semantic content from distance-to-baseline, layerwise covariance, or other geometric properties.

**Required repair.** Build placebo deltas, not placebo source states. Permute the observed aligned deltas across positions/conversations, enforce derangement, and rescale each row to the corresponding treatment-delta norm. Add covariance-matched random rotations/sign flips. Report delta norms, cosine similarity, affected-slot count, model-output KL, and target-logit displacement for treatment and every placebo. A content-specific conclusion requires matched perturbations that differ primarily in content correspondence.

### 5. High: the primary metric is an authored-string proxy, not recovered behavior

**Observed.** The harness tokenizes each plant's single `gold` string and teacher-forces it after the probe (`src/cross_arch_probe.py`, approximately lines 2825-2859). Some golds are descriptions of an answer rather than natural assistant continuations; for example, stance targets can begin with phrases such as “Suggests urgency tactics...”. Multiple probes vary the question, not the target paraphrase. Six heterogeneous categories are aggregated.

**Implication.** Mean target-token log probability can be sensitive to stylistic phrasing and tokenization, and a small change need not yield a more correct answer or task success. It is useful as a sensitive mechanistic proxy, but not as sufficient evidence of semantic continuity in behavior.

**Required repair.** Use several independently authored gold paraphrases, or preferably a likelihood-ratio outcome comparing correct answers with matched plausible distractors. Add blinded generated-answer scoring with identical randomized prompts for all arms, independent judges, inter-rater agreement, and a precommitted single dose. Treat actual task success as primary in an agent deployment study.

### 6. High: leakage auditing is literal and cannot exclude paraphrased leakage

**Observed.** `src/audit_corpus.py` uses literal keyword substring searches in early and tail regions (approximately lines 16-43). It does not detect semantic paraphrases. Its `in_middle` condition requires any keyword, while other keyword scoring can require all. The corpus is heterogeneous: early conversations contain many truncated Qwen3-4B sampled replies; later ones are externally authored.

**Implication.** A model reply may paraphrase the plant into the tail or other retained text without triggering the audit. This can reduce the need for cache grafting or change what the outcome measures.

**Required repair.** Run a blinded semantic leakage audit of early context, retained tail, generated summary, and probe, with a manual stratified sample and adjudication. Record leakage class per plant rather than silently filtering it.

### 7. High: the statistics support a bounded pilot null, not a definitive null

**Observed.** Conversation-cluster bootstrap code is present (`src/cross_arch_probe.py`, approximately lines 292-329 and 743-796), a major improvement over plant-level pseudoreplication. The estimator pools plant observations after resampling conversations, so larger conversations retain more weight. Equal-conversation and plant-weighted estimates differ modestly but do not reverse the current held-out conclusion (for example, per-layer about -0.0026 plant-weighted versus +0.0073 equal-conversation).

**Observed.** There are only 18 independent held-out conversation clusters. Pointwise intervals are reported over several configurations, categories, and compression levels without a single multiplicity-adjusted confirmatory family. The compression analysis does not use a paired repeated-measures slope/trend test. `raw_EB` is described as “bounded,” but a log-probability difference is not mathematically bounded.

**Inference.** The held-out confidence intervals exclude large effects but permit small effects. Rough variance scaling suggests that shrinking a roughly +/-0.04 interval to +/-0.01 would require on the order of 288 similarly variable conversations, although actual power must be estimated from a preregistered simulation.

**Required repair.** Predeclare one primary estimand/configuration, a smallest effect size of interest, and an equivalence test. Cluster by the independent assignment unit (conversation or task), and consider an equal-conversation estimand or hierarchical model. Test compression as a paired within-conversation trend. Treat the remaining variants/categories as exploratory or control familywise/FDR error.

### 8. High: identity gates are thoughtful but do not prove exact production equivalence

**Observed strengths.** The repository has MLX L0/L1/L3 ladder scripts, per-run alpha-zero and source-equals-destination identity checks, a live-change check, forced `DynamicCache` shape/type checks, position-region matching, and exact model revision/dtype in several manifests.

**Observed limitations.** The HF ladder defaults to a small model and does not demonstrate full alpha-zero/alpha-one transplant identity on every production checkpoint/configuration. The cross-architecture smoke checks compare averaged per-token/per-probe log probabilities at tolerance about 5e-3; cancellation can hide tokenwise errors. The README's “bit-for-bit” wording is therefore inaccurate. The normal `tests/` directory mainly covers transcript/note tooling, not cache surgery or scientific scoring.

**Required repair.** Gate every exact production checkpoint, revision, dtype, tokenizer, attention backend, batching mode, and library version. Compare full tokenwise logits and cache tensors with maximum error, not only averaged likelihood. Add incremental-generation versus full-prefill cache equivalence, alpha-zero exactness, alpha-one source reconstruction where defined, exact summary-token reconstruction, and alignment-coverage assertions to automated tests.

### 9. High: checkpointing is strong, but render fingerprints and manifests omit decisive provenance

**Observed strengths.** Cross-architecture checkpoints use atomic fsync-and-replace writes and preserve rendered conversations, summaries, traces, and configuration (`src/cross_arch_probe.py`, approximately lines 1143-1152). This is excellent practice.

**Observed gaps.** The render fingerprint (approximately lines 1169-1197) omits a scaffold-content hash, resolved model/tokenizer revisions, native batch composition, library versions, and dtype. The code acknowledges that batch composition can alter bf16 greedy outputs (approximately lines 2375-2384). Several inspected result manifests contain `code.git_commit: null`, although the paper says the exact commit is recorded. `src/provenance.py` permits null commits. Cross-architecture top-level output naming is fixed by model slug; wrappers later copy to unique timestamped files, so uniqueness is not enforced by the harness itself.

**Implication.** A stale render can be accepted after meaningful input/runtime changes, and a result may not identify the code that produced it. Source render and batched render are not interchangeable controls when batch-dependent kernels can alter generation.

**Required repair.** Fingerprint the complete canonical token sequence plus scaffold file content, model and tokenizer resolved revisions, dtype, attention backend, library versions, seed, batching mode, and exact batch membership/order. Fail closed on a missing git commit in a clean tracked run. Make unique output paths intrinsic to the harness and refuse to reuse a checkpoint with any fingerprint mismatch. Include an explicit source-vs-batched control on the exact production configuration if batching is part of generation.

### 10. High: SWE-Gym artifacts do not save sufficient render state

**Observed.** `src/run_swegym_hf.py` loads external OpenHands trajectories, cuts them 60-85% before an assistant action, retains roughly the final quarter, generates a summary, and predicts up to 600 target tokens (approximately lines 158-176 and 323-404). Per-example result JSONs record summary token count, arm scores, and parsed gold action. They do not preserve the exact generated summary text/token IDs, full source/cut/tail context, exact target text/token IDs, generation prefix, or per-region aligned token map. The dataset parquet is a local working artifact rather than a committed experiment record, and the manifest lacks a dataset-content hash/version. Inspected SWE manifests also have a null code commit.

**Observed implementation risk.** The loader hardcodes `torch.bfloat16` (approximately lines 195-199), while the manifest separately records a requested environment dtype; a non-bf16 request could therefore be misreported. Output directories are tag-based, and existing parseable `tNNNN` results are skipped without checking a full experiment fingerprint (approximately lines 206-208 and 304-313). Unique wrapper tags reduce risk but the harness does not enforce it.

**Implication.** The expensive generated summary/render cannot be reproduced or audited exactly from committed artifacts. This falls short of the repository's own “SAVE EVERY RENDER” requirement.

**Required repair.** For every trajectory, commit a compact checkpoint containing the canonical full/cut/tail messages, exact source token IDs or content hashes plus immutable dataset revision, exact summary text and IDs, summary generation prefix/parameters, target text and IDs, aligned regions, fingerprints, traces, arms, and model/tokenizer/library/code provenance. Assert that recorded dtype equals the actual loaded dtype. Refuse skip/reuse unless the complete fingerprint matches.

### 11. High: the SWE-Gym scalar positive failed independent replication; tuned champion remains provisional

**Observed.** The initial apparent scalar alpha=.75 gains of roughly +0.013/+0.016 came from reruns of the same original 75 trajectories, so they are test-retest reliability rather than independent replication. On the disjoint 98-trajectory pool the estimate was about -0.0017. The latest note reports an in-domain selected map at +0.0117 with CI [+0.0063, +0.0172] on a 57-example evaluation split after selection on 41 examples. An untouched external confirmation on the original 75 is queued/not yet in the audited artifacts.

**Observed nuance.** The 98-item pool and split are first eligible indices rather than randomized draws, so source/order/task distribution can differ. The in-domain map is the union of eight regions selected after exploring the tune subset. `scripts/analyze_swegym_tune.py` labels one output “vs scalar .75 on EVAL” but prints scalar `E_tuned-B`, not selected-minus-scalar.

**Implication.** The scalar result is currently null out of sample. The tuned result is a legitimate internal train/evaluation split, but still exploratory after multiple looks and not externally confirmed. SWE-Gym is also a next-action likelihood/exact-match proxy, not repository repair success.

**Required repair.** Complete the untouched external confirmation without changing the selected map. Then preregister and evaluate on a randomly sampled, distribution-stratified new set. Cluster inference by repository/task if multiple cuts share a task. Preserve next-action likelihood as secondary and measure actual agent success as primary.

### 12. Medium-high: the H-pack honesty result is not evidence for semantic ValueGraft

**Observed.** The H-pack arm packs keys and values in an out-of-distribution layout: sink tokens followed by summary generation IDs, no retained tail, then a synthetic user suffix (`src/run_phase2.py`, approximately lines 65-145). The scored 30B behavioral artifacts are 4-bit MLX rather than the bf16 configuration implied in some claim documents. The observed pattern is anti-fabrication, not recovery: H-pack changed fabrication/admission rates but achieved zero correct responses; wrong-summary controls sometimes produced equal or stronger effects, including 24/24 admissions on decoys.

**Implication.** This intervention can alter calibration or refusal/admission behavior, but its content-specific semantic interpretation is contradicted by its own controls. It should not be combined with the main ValueGraft evidence.

**Required repair.** Report H-pack as an OOD packing/calibration finding only, with the wrong-summary control foregrounded. Do not use it as evidence that generation-time semantic state was recovered.

### 13. Medium: cross-architecture claims are exploratory and confounded

**Observed.** Models differ in architecture, tokenizer, rendered conversation nativeness, and sometimes precision/runtime. Per-token log-likelihood magnitudes are not directly comparable across tokenizers. Only a small set of model families is observed; proposed architecture predictors such as QK normalization were not confirmed, and some ablations broke generation.

**Implication.** Within-model signs are interpretable as exploratory results. Architecture-level causal explanations are not. Negative poles establish that the intervention can harm a model/configuration, not why.

**Required repair.** Use a common frozen text corpus plus a separate model-native corpus, report both, normalize outcomes within model, and vary one architectural feature at a time where possible. Treat architecture correlates as hypotheses until tested on new models.

### 14. Medium: tuning and validation target different domains and metrics

**Observed.** `src/run_tune_hf.py` tunes regions on generic held-out final-assistant continuation over c01-c06 and n01-n04 (approximately lines 46-149), while the main validation measures planted gold recovery. All tuning conversation replies are foreign to the target model. Per-head selection considers many slots using only about ten contexts.

**Implication.** The clean outer held-out validation protects against direct reuse of its outcomes, but the chosen map may be poorly matched to the recovery estimand, and head selection can be noisy.

**Required repair.** If the goal is to give the method its best chance, use nested tuning on the exact target domain and metric with an untouched outer test. Include summary-only/tail-only factors and predeclare the selection rule. Do not revise the map after viewing the outer test.

## What is methodologically sound and worth retaining

- The incident ledger clearly labels void and quarantined runs instead of deleting inconvenient evidence.
- Conversation-level resampling addresses the largest earlier pseudoreplication problem.
- The holdout boundary between tuning and main validation is conceptually sound.
- Alpha-zero, identity, live-change, cache-shape, and alignment checks are the right classes of engineering controls, even though they need stricter tokenwise production gates.
- Atomic checkpointing and retained render text in the cross-architecture harness are strong reproducibility practices.
- The project distinguishes mechanistic likelihood proxies from judge/behavioral outcomes more carefully in recent notes than in older prose.
- The independent 98-trajectory SWE result was allowed to overturn the earlier optimistic scalar narrative. That is exactly the right scientific response.

## Interpretation of the evidence

### Supported now

1. Selected value-state interventions are technically capable of changing model likelihoods and sometimes harming them.
2. In the inspected held-out synthetic setup, there is no evidence of a large average improvement from the selected summary+tail graft. The intervals permit smaller effects.
3. Naive scalar transfer on SWE-Gym did not generalize to the independent 98-trajectory pool.
4. A map tuned within SWE-Gym produced a small positive internal held-out likelihood effect; external confirmation is pending.
5. OOD KV packing can change admission/fabrication behavior, but the effect is not content-specific recovery.

### Not supported now

1. A “definitive null” for generation-time semantic continuity in general.
2. A valid compression-severity null across ultra/brief/medium/realistic levels.
3. Content specificity based on current shuffled/Gaussian placebos.
4. Recovery attributable specifically to summary-token values rather than tail values.
5. Model-native serving relevance from the main held-out synthetic validation.
6. Real coding-agent performance improvement.
7. A cross-architecture law explaining which models benefit.

## Highest-value next experiments

### Gate 0: repair provenance and the broken compression reconstruction

Before more scale, add exact generation-prefix/summary-ID persistence, complete render fingerprints, non-null code/data hashes, and tokenwise production identity tests. Rerun only the corrupted compression cells. This is necessary to know what later experiments mean.

### Gate 1: resolve mechanism with a small factorial, not another broad sweep

On an untouched model-native corpus, compare:

1. baseline;
2. summary-only aligned delta;
3. tail-only aligned delta;
4. summary+tail aligned delta;
5. per-row norm/covariance-matched deranged delta placebo;
6. wrong-conversation but norm-matched delta;
7. alpha-zero identity.

Report target likelihood ratio, generated-answer correctness, output KL, delta norms, and slot count. This single design answers the two largest interpretability gaps: region attribution and content specificity.

### Gate 2: adequately powered confirmatory synthetic study

Predeclare one configuration, one primary metric, one SESOI, and equivalence bounds. Use model-native renders from the exact target configuration, balanced conversation sizes, semantic leakage labels, multiple gold paraphrases, and enough independent conversations to reach the desired interval width. Power from conversation-level pilot variance, not plant count.

### Gate 3: finish the already-defined SWE external confirmation

Freeze the eight-region map and analysis before touching the original 75. Preserve every exact render and manifest. The outcome should be treated as confirmatory only if no choices are revised after inspection.

## How to test this on real coding agents

This is worth doing **only after** exact online cache capture/replay and perturbation matching pass the small gates above. A real-agent experiment would materially improve external validity because it tests long-horizon task success, but it is expensive and easy to confound.

Recommended design:

1. Use one capable open-weight agent model and its ordinary tool loop. Establish a non-compacted competence floor first.
2. Instrument the serving stack to save the model's actual incremental generation-time K/V state, exact token IDs, model revision, attention backend, dtype, and summary-generation prefix. Do not reconstruct this state by full prefill unless tokenwise/cache equivalence has been demonstrated on the exact stack.
3. At the natural production compaction boundary, fork a paired run from the same complete state into baseline compaction and frozen graft treatment. Include norm-matched deranged and wrong-task controls on a smaller mechanistic subset.
4. Use the production condenser and ordinary agent policy. Do not change prompt wording, tool affordances, context allocation, decoding, or budget between arms.
5. Randomize arm labels and execution order. Use several seeds per task, but cluster inference at task/repository level. Avoid sharing writable worktrees across arms.
6. Primary outcome: tests passed / issue resolved under a fixed token and wall-clock budget. Secondary outcomes: regression rate, tool calls, time, next-action likelihood, summary fidelity, and semantic-probe scores.
7. Stratify tasks by whether information needed after compaction appeared only before compaction, was repeated in the retained tail, or was captured in the summary. This identifies where grafting could plausibly add value.
8. Save the complete trajectory, summary text/IDs, compacted prompt, old/fresh cache metadata, aligned map, treatment delta statistics, patch, test logs, and costs for every arm.
9. Predeclare one treatment map and stop rule. Analyze paired task-level differences with confidence intervals and an equivalence region.

A cheap precursor is a replay benchmark: take completed model-native agent trajectories, cut at observed compaction boundaries, and score the next 100-600 tokens under baseline versus graft. That is still only a proxy, but it can screen configurations before expensive live forks. The current SWE-Gym experiment resembles this precursor, except the trajectories are foreign to Qwen and the artifacts do not preserve enough exact render state.

## Bottom line

The honest scientific result at this snapshot is narrower and more valuable than either a positive headline or a universal failure claim: **under one carefully instrumented but non-model-native synthetic setup, a preselected summary+tail value graft produced no detectable average benefit, with uncertainty still large enough to permit small gains.** The independent SWE scalar result is also null. The new tuned SWE signal is the one credible positive lead, but it remains provisional until its untouched external test is complete and its render/provenance artifacts are made reproducible.

The two most important repairs are not more model scale. They are (1) exact generation-prefix/token provenance, especially for the broken compression sweep and SWE renders, and (2) perturbation-matched placebos plus summary-versus-tail factorials. Without those, even a statistically significant future result would remain mechanistically ambiguous. With them, a modestly larger model-native confirmatory study could support a much more defensible answer.
