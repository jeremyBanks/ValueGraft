_The day combined a major maturation of the notes-archival tooling — culminating
in this daily/overall meta-summary system itself — with a research crisis in the
ValueGraft project: both headline behavioral results were traced to precision
and arm-provenance errors, triggering a full audit, a corrected framing, and a
redirected validation plan now pending a champion-configuration experiment._

## Notes-infrastructure work

The conversation-archive tooling was substantially rebuilt: a 6-hour
note-duration split policy, filtering of Claude/Codex compaction-scaffolding
messages out of summarizer inputs (a ~4.25% prompt-size reduction), a
git-blob-keyed date cache to eliminate repeated history-walking, and a bulk
renormalization of ~101 archive filenames that had drifted out of sequence
during an earlier naming-rule change. This directly enabled the new two-layer
meta-summary system — per-day summaries at `notes/YYYYMMDD.md` (this file's own
format) and a synthesized `notes/README.md` overview — with size-capped
head/tail excerpting for long source notes, a shared sensitive-topic filter
(dotenv-configurable), and a policy that `deno fmt` must run before manifest
hashing. A live regeneration pass surfaced and fixed two further bugs: a
participant-block sync regex that could delete note content, and unstable
renaming caused by trusting git rename history (fixed by seeding dates from the
conversation manifest instead). A stray local git-identity override briefly
reattributed commits to a Codex identity project-wide; it was caught and
reverted, with future Codex attribution deferred to per-commit trailers rather
than repo config. Separately, the scheduled automation heartbeat intended to
trigger periodic archive updates missed its firing window twice during the day
and had to be run manually both times — noted as a confirmed reliability gap,
with manual invocation plus its validation checks (filename/meta-summary dry
runs, manifest integrity, forbidden-term scan) as the working fallback.

## ValueGraft: reproduction collapse and precision/provenance audit

An independent re-render of the same twelve reference conversations, run
specifically to test the project's judged-sense recovery headline under clean
current code, collapsed the previously reported +12pp effect to +1.0pp (CI
spanning zero). Disentangling the drop showed it was overwhelmingly a rendering
artifact rather than judge recalibration (+12.0→+8.7 from judge changes,
+8.7→+1.0 from the render itself) — the same render-fragility pattern already
seen in an earlier referent-logprob failure. With both of the project's positive
recovery metrics now shown non-reproducing at n=12, a deep audit (multiple Fable
passes plus a subagent-mined environment retrospective) reconstructed the
project's actual evidentiary state from disk rather than from prior summaries:

- **No on-disk result is simultaneously bf16 and the current value-only
  ValueGraft method as a validated positive.** The recovery headline and the
  honesty/anti-fabrication headline were both run only on the local 4-bit MLX
  backend; a paper draft had briefly and incorrectly labeled the honesty result
  bf16 before an adversarial review caught it.
- **The honesty result's intervention arm (H-pack) is not ValueGraft.** H-pack
  retains write-time keys and values in a packed layout with no conversation
  tail — a different, coupled-KV intervention from the paper's named value-only
  method (α_K=0). A control using a _different_ conversation's state suppressed
  fabrication just as effectively, indicating the effect is
  packed-layout-driven, not content-specific.
- **The bf16, placebo-controlled, value-only test of recovery (`effect_bound`)
  is a preregistered null** on two models (Qwen3.6-27B and Qwen3-30B-A3B),
  though it does establish that value grafting is content-specific and
  non-destructive relative to a random-value placebo.
- **The one genuine bf16, value-only positive on disk is small:** a SWE-Gym
  teacher-forced-logprob effect (+0.0156 nats, CI [+0.005, +0.027], excludes
  zero, changes greedy output on 49/75 tasks) — but measured under a
  deliberately terse ("brief") summary condition designed to handicap the
  compacted baseline, and at scalar α=0.75 rather than the tuned champion
  configuration.

A subsequent provenance ledger formalized this discipline by marking each
controlled variable (model, dtype, quantization, intervention/α, metric, summary
condition) as **PROVEN** (recorded in the artifact) versus **INFERRED**
(reconstructed from a directory name or code default) for existing results —
finding that even the SWE-Gym anchor's dtype, alpha, and summary condition were
all inferred, not recorded. Manifest-stamping instrumentation was added to the
four experiment harnesses so future runs self-document these fields at runtime
rather than relying on naming conventions.

Separately, a same-day pass scored previously-unscored bf16 honesty answers
(`results/phase2_30b_bf16_verdicts.json`, present but not yet committed) and
confirmed the packed-KV admission effect replicates at full precision (decoy
+62.5pp, evicted-fact +20.8pp, both CI-significant) — a real, bf16-confirmed
finding, but still scoped as supporting evidence for a packed-layout regime
rather than a ValueGraft cornerstone.

## Framing and terminology clarifications

The owner corrected the historical narrative embedded in earlier generated
summaries: the mitigation-first framing ("does a deployable intervention offset
compaction damage") was the owner's intent from the start, not a pivot triggered
by external review — the earlier "mechanism as the finding" framing was an agent
misunderstanding, corrected once the owner noticed it. Future summaries should
not narrate this as a reframing driven by review. Separately, analysis of the
"native-render" premise split it into two claims: the requirement that the graft
use the model's own self-generated summary is verified and mechanistically
clean; the requirement that replies also be natively rendered (not authored) is
not established — a second independent native draw reproduced the
authored-condition effect, showing the apparent collapse was render noise of
comparable magnitude to the effect itself, not a validity fix.

## Current plan and open questions

Paper construction is paused pending one decisive, owner-directed experiment:
whether the previously-untested per-layer/per-head "champion" tuned
configuration produces a genuinely content-specific recovery effect (via
placebo-controlled, conversation-clustered CIs on held-out conversations) or
merely amplifies the same generic, content-independent effect already
characterized as null. This is being run per-quantization (4-bit first, then
bf16, each with its own tuning pass) with a parallel per-head variant designed
to check whether head-level granularity beats the existing per-layer selection.
Fable's standing recommendation is that, absent a positive result from this
experiment, the honest deliverable is either a bounding/negative paper (led by
the bf16 null plus the honesty dissociation) or a candid process postmortem,
rather than any "recovery" claim; separate owner guidance for the next paper
draft specifies dropping internal jargon (arm names, "H-pack," etc.), curbing
repetitive "honest/honesty" framing language, and having Fable author the prose
with full framing latitude, subject to a dedicated fresh-eyes readability/flow
review distinct from adversarial fact-checking passes. Unresolved operationally:
the pod-side dependency environment remains without a single source of truth (a
live contradiction in `transformers` version pins across job scripts, missing
`pandas`/`pyarrow` in most pod bootstraps), with a shared `pod_env.sh` plus
fail-closed preflight check recommended but not yet built.
