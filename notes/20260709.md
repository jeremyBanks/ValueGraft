_The day combined a large tooling overhaul of the notes/conversation-archive
system — duration policies, compaction-scaffolding filtering, archive renaming,
and a new two-layer meta-summary system — with mainline research progress on the
block-design reproduction run and two more architecture-pole results, plus a
provenance correction to the project's historical framing narrative and a note
on unreliable scheduled automation._

## Notes tooling and archive infrastructure

The bulk of the day's engineering went into the notes/conversation-archive
pipeline itself. A 6-hour conversation-span duration policy was added to the
note updater, triggering a regeneration of existing notes into more granular
splits. A structural filter was added to exclude Claude Code's
`isCompactSummary` continuation messages and Codex's
`compacted`/`replacement_history` rows from summarizer input — these had been
silently inflating prompt size (~4.25% of characters across affected notes)
without adding content; the note updater retains these rows internally for
manifest message-index stability but omits them from summarizer-facing text.

Archive filename normalization was found to be in a non-contiguous,
mid-migration state (101 of 112 files needing renaming) and was fixed via a
bulk-commit rename pass. A recurring instability in this renaming (files
oscillating between successive runs) was traced to git rename history being an
unreliable date source once a note has been renamed multiple times; the fix
seeds the date cache from the conversation manifest (which stores each note's
canonical first-message date) rather than git history, for conversation notes
specifically.

**New artifact: daily meta-summaries and overall README.** A two-layer
summarization system was built: per-UTC-day summaries at `notes/YYYYMMDD.md`
(this document's own format) and a whole-project `notes/README.md` synthesized
from all daily summaries as a process/history narrative ending in current state.
Regeneration is keyed by manifest comparison of source-note git blob IDs, not
filenames, so renames don't force rebuilds. Non-conversation notes over 8 KiB
are shown to the summarizer as a 6 KiB head + 2 KiB tail excerpt with an
explicit omission marker; conversation-summary notes get a larger 16 KiB/12+4
KiB threshold. A shared, configurable forbid-regex/sensitive-topic filter
(`scripts/notes_summary_filters.py`) was added across both generator layers,
loadable via CLI flag, environment variable, or a gitignored dotenv file.
`deno fmt` is now run on generated output before manifest hashing in both
generators, established as policy rather than a manual step. `notes/AGENTS.md`
was rewritten to clarify that filename prefixing, manifest updates, and summary
regeneration are script-owned, not agent-managed.

A repo-local git identity change (setting `.git/config` to a Codex-specific
author, intended to distinguish agent commits) had the unintended effect of
silently reattributing all subsequent commits repo-wide; this was caught and
reverted, with no tracked files altered. Going forward, agent-specific
attribution should use per-command author/committer environment variables or
commit trailers, not repo-level git config changes.

A live-tail regeneration pass also exposed and fixed a participant-block sync
regex bug capable of deleting note content under certain conditions; this was
patched and covered with a regression test before the final commit-and-push.

**Automation reliability caveat.** A scheduled in-app heartbeat intended to
trigger a periodic archive update fired roughly two hours late and did not
complete the expected work; it was remediated manually. The heartbeat/automation
mechanism is now flagged as unreliable for this purpose — future agents should
verify actual execution rather than assume it ran, with manual dry-run checks as
the fallback.

## Reproduction run and architecture-pole results

Before trusting the newly built per-conversation
checkpointing/render-persistence system for the block-design reproduction
re-run, it was sent to Fable for adversarial review (per standing
GPU-code-review practice) rather than accepted on the implementer's
self-certified validation, which cited an uncommitted, unverifiable test script.
Fable found a genuine silent-correctness bug: in relative-floor mode, resuming a
run could drop a conversation's `lp_A` values from the pooled competence floor
if that conversation had empty A↔B alignment, changing the computed floor (and
downstream gating/CI) relative to an uninterrupted run. The fix was implemented,
re-reviewed by Fable, and validated with a negative control showing
FRESH/RESUME/KILL-SIM floors matching under the fix (−9.499) versus drifting
under the pre-fix code (−10.126) — confirming the test actually detects the bug.
A separate launcher bug (missing `SC_CONV_START` and relative-floor-mode
propagation to remote jobs) was found and fixed before launch, which would
otherwise have caused all three block cells to silently start at the same
conversation offset.

Three pods were launched for the reproduction (Qwen3-30B-A3B, relative floor,
checkpointing enabled): b0 = baseline c01–c12, b1 = fresh c13–c24, b2 = fresh
c25–c36. A launcher chaining hang (previously identified pattern) required
launching b1/b2 independently; conversation-range offsets were confirmed correct
on all three pods afterward. Checkpointing was confirmed working in production
(accumulating per-conversation checkpoints on disk mid-run).

b0 (baseline) finished first, showing referent CI [−0.068, +0.090] (mid ≈
+0.012) — an apparent non-reproduction of the original +0.156 anchor point
estimate. This initially read as an apparatus failure, compounded by an
informational (non-gating) `graft_direction_ok: False` flag firing on this and
other models; both concerns were walked back after re-reading the code confirmed
the real smoke gates passed and the flag is not a validity check. The more
defensible provisional reading is that the original +0.10–0.156 estimate was
itself noisy/underpowered (n=12) combined with hardware-nondeterministic MoE
routing across pods, rather than a broken graft — but this is explicitly
provisional pending the full pooled b0+b1+b2 block analysis, which had not
completed by day's end (b1 mid-scoring at 5/12, b2 still rendering).

Two more architecture-pole results landed and were banked in FINDINGS.md:

- **Qwen3-32B** (dense, pair-B, same vendor/QK-norm status as the MoE anchor):
  referent CI [−0.063, +0.010] (null), all other categories negative — a clean
  within-Qwen MoE-vs-dense reversal against the MoE anchor's +0.10.
- **Qwen2.5-32B** (dense, no QK-norm): referent [−0.303, −0.157], sense −0.42,
  stance −0.18 — the most strongly harmful result of the sweep so far.

With both dense poles now null/negative against the positive MoE anchor and a
weak Mistral positive, the architecture map skews MoE-positive/dense-negative —
but this is explicitly flagged as ambiguous between a real MoE-vs-dense
mechanism and the effect being largely specific to the model it was originally
developed on. The block reproduction result is the designated disambiguator and
is not to be treated as resolved until the pooled read is in hand.

## Decisions and standing practices

- The complete unresolved picture (reproduction result, full architecture-pole
  map, and the model-specificity robustness concern) is to be put to Fable
  **un-anchored** — raw results plus a pointer to notes/, not a curated summary
  — before any paper edits or conclusions, once the pooled block analysis is
  available.
- Push notifications are now standing practice for major results/milestones (bug
  findings, fixes cleared, run launches) rather than routine progress ticks.
- **Framing-provenance correction (owner-issued):** the existing daily summaries
  and README narrate the 2026-07-05 shift from a mechanism-as-finding framing to
  a mitigation framing as a _redirection_ prompted by external review. The owner
  states this is inaccurate: the mitigation-oriented framing was the owner's
  intent from the start, and the mechanism-framing was an agent misunderstanding
  that took time to surface and correct — not a change in project goals. This is
  recorded as an additive correction rather than a rewrite of the existing
  (agent-perspective) generated summaries; future framing narration, including
  in the paper, should describe the correction this way rather than as a project
  pivot.
- Standing rule reaffirmed: "compaction destroys context-conditioned state" is
  baseline/denominator, never a finding.
