# MANDATORY METHODS & DATA-PROVENANCE DOCUMENTATION — the paper MUST satisfy this

> **Why this file exists (07-08):** Every prior version of the writeup FAILED to document
> the structural/experimental methodology — above all, **who or what generated each piece
> of data**. That omission is not a stylistic gap; it is the difference between a
> reproducible, trustable result and an anecdote. This session lost HOURS to exactly one
> such undocumented detail (whether a conversation's assistant replies were the test
> model's own or written elsewhere — it turned out to determine whether the effect even
> appears). **Shipping the paper without the items below is unacceptable. Do not write a
> methods section that skips any of these.** Any agent writing the paper reads this first.

## 1. DATA PROVENANCE — for EVERY token in the experiment, state WHO/WHAT produced it
This is the section that was missing and matters most. For each conversation, document the
origin and exact generation procedure of each component:

- **System prompt** — authored by us? templated? give it.
- **User turns / prompts** — AUTHORED by us (the experimenters), not model-generated. Say so explicitly and say WHY (real user prompts aren't model-generated; a result that depended on model-generated prompts would be invalid).
- **The planted manipulation** (referent/sense/stance/ruled_out/evicted_fact/strong_prior facts) — authored; how; the categories; how many; the design.
- **Assistant replies (the conversation body)** — GENERATED IN-CONTEXT BY THE TEST MODEL ITSELF (per-model-native design). State: this is native per model, why that matters (the graft re-injects the model's own write-time values, so context must be what the model itself would produce), the exact generation config (greedy vs temperature, max reply length, seed, cache handling). **If any replies were generated by a DIFFERENT model, that must be stated loudly** — it is the difference between valid and invalid, as we learned.
- **The compaction summary** — SELF-GENERATED by the test model (the model summarizes its own conversation). State the summary prompt, the generation config, and the prior finding that a FOREIGN summary suppresses the effect (so self-gen is required, and it matches reality).
- **The gold continuation** (the teacher-forced target the metric scores) — derived from the PLANTED FACTS, SHARED across models, NOT model-generated. State why (the difference metric cancels target-nativeness only if the target is shared).

## 2. PROCEDURES — exact, reproducible
- **Compaction / B-context construction**: exactly how the compacted context is built (system + summary-as-assistant-note + tail), per template family.
- **The graft**: write-time KV snapshot, which vectors (VALUES; keys neutral), alpha, the alignment method (difflib positional-within-region — and the history: a strict variant was tried and reverted because it breaks on thinking-model self-gen).
- **The metric**: raw_EB = lp_E − lp_B, teacher-forced on the shared gold; the robust estimator (raw E−B + bootstrap CIs, NOT the retired mean-of-ratio); per-conversation cluster bootstrap; the categories.
- **Gates/exclusions** (design v2.1): per-model HEADROOM (A−B gap) normalization + threshold; TASK-COMPETENCE (lp_A) inclusion; floor handling (no gap = uninterpretable, NOT "harm"). State every exclusion rule and how many were excluded.

## 3. MODELS — EXACT checkpoint ids, no ambiguity
- Give the FULL HF repo id of every model (e.g. `Qwen/Qwen3-30B-A3B-Instruct-2507`, NOT "Qwen3-30B"). This session lost hours to running the THINKING `Qwen3-30B-A3B` when the result was measured on the NON-thinking `-Instruct-2507`. Thinking vs non-thinking, base vs instruct, the date-stamped variant — ALL must be specified.
- Per-model: the attention-geometry hyperparameters used as predictors (n_kv_heads, head_dim, GQA ratio, QK-norm presence, RoPE theta, layers), read from config, reported in a table.

## 4. DESIGN RATIONALE / SCOPE CONDITIONS — document the WHY, not just the WHAT
- The per-model-native (matched-scaffold) design and WHY (nativeness is part of the mechanism; each model measured on conversations it would actually produce). This is a scope condition and a finding, not a footnote.
- The pre-registered geometry hypothesis + that it was pre-registered before the 16-run.
- The two within-vendor dense/MoE de-confound pairs and why they carry primary inferential weight.

## 5. REPRODUCIBILITY
- Seeds, determinism, the single filterable entry point, exact model ids, exact data (or its generation procedure). A reader with a GPU must be able to reproduce every number.

## SCIENTIFIC NUANCES & SCOPE CONDITIONS — the paper MUST state these (added 07-08, owner emphatic)
Beyond data provenance, these design decisions / scope conditions / mechanistic nuances emerged
this session and MUST be stated clearly. A reader who doesn't know them cannot interpret or reproduce
the result. Do not bury or omit any:

1. NATIVENESS SCOPE CONDITION (central): the graft recovers evicted meaning ONLY for the model's OWN
   NATIVE context. Evidence: foreign assistant replies collapse the effect (raw_EB +0.009 vs native
   +0.12, same model, real A-B gap present); a foreign SUMMARY also suppresses it. The graft re-injects
   the model's own write-time values, so the context (assistant replies) AND the summary must be what
   THAT model produced. This is a feature (it makes the mechanism specific, kills "any KV re-injection
   helps"), and it matches deployment (a real conversation's replies ARE the model's own). STATE it as
   a scope condition + finding, not a footnote.
2. PER-MODEL-NATIVE DESIGN: models were measured on DIFFERENT conversations — same shared SCAFFOLD
   (planted facts + user prompts + gold), but each model generated its OWN in-context assistant replies +
   its OWN self-gen summary. State this explicitly and why (ecological validity; a shared foreign corpus
   would confound the cross-arch SIGN with per-model nativeness).
3. EXACT CHECKPOINTS: give full HF ids incl. thinking-vs-instruct (the +0.12 is on the NON-thinking
   Qwen3-30B-A3B-Instruct-2507; the thinking Qwen3-30B-A3B behaves differently — a wrong-checkpoint run
   cost us hours). Report per-model attention geometry (n_kv_heads, head_dim, GQA, QK-norm, RoPE, layers).
4. METRIC = raw_EB = lp_E - lp_B on a SHARED gold continuation (from the planted facts, not model-
   generated) -> the difference cancels target-nativeness, so the SIGN is the robust quantity. Robust
   estimator: raw E-B + bootstrap CI over CONVERSATIONS (the retired mean-of-ratio was Cauchy-unstable).
   raw_EB normalized by per-model HEADROOM (A-B gap).
5. GATES: headroom floor (a category the summary preserved has no A-B gap -> FLOORED, uninterpretable,
   NOT "harm"); task-competence (lp_A); coherence-screen the model-filled replies. Report N excluded.
6. ALIGNMENT: difflib positional-within-region matching (summary<->summary, tail<->tail); a strict exact-
   span variant was tried and REVERTED because it breaks on thinking-model self-gen tokenization. State
   the method + that it's positional-within-region (not spurious cross-conversation matching).
7. THE DISSOCIATION: referent > sense > stance~0 — graft helps where compaction did damage (evicted
   sense/referents), null where the summary already sufficed (stance). This is the core signature.
8. KEYS NEUTRAL: values are the operative axis (keys ~neutral); state it, don't overclaim keys.
9. ARCHITECTURE BOUNDARIES: MLA models (DeepSeek/Kimi) excluded by design (no per-head values to graft);
   sliding-window (Gemma) may be UNSUPPORTED (padded snapshot) — report which models were UNSUPPORTED + why.
10. HONEST BOUNDS: single cross-model non-replications, small-N per-model CIs straddling zero (report as
    inconclusive-per-model, not null), and the pre-registered geometry hypothesis (state it was pre-registered).

RULE: brief Fable + critics + Codex to check the paper states each of 1-10 AND the data provenance above.
Omitting any is a blocking review failure.
