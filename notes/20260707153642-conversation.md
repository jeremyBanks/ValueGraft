Microtest / synthetic harness exploration by Codex:

- User pasted a “referent recovery harness” proposal. Codex first saved it
  exactly, then later cleaned it up, removed stray span tags, and attributed it
  near the top to Gemini 3.1 Pro using a clearer offline-summary /
  teacher-forced extraction framing.
- Codex created a new isolated `referent_recovery_microtest/` directory for
  cheap local experiments, explicitly avoiding the active `results/kv_sweep`
  work.
- First cheap gate: tiny sparse-summary referent tasks, teacher-forced only.
  Result was a negative gate: full context beat compacted context on all cases
  (`A > B`), but every graft policy made the correct continuation less likely
  than the compacted baseline. Conclusion: this exact sparse-summary harness
  should not be scaled as-is.
- Codex then did a broader problem-shape search. Key design insight: the failed
  AST/Z85 version demanded recovery of high-entropy arbitrary payload; better
  candidate tasks hide low-entropy relations behind labels.
- Families tested included sense labels, policy choices, bug-fix labels,
  low-entropy transforms, and format-order tasks. Best early families were:
  - `policy_choice`: stable positive lane
  - `low_entropy_transform`: weaker overall but more interesting for K-only
    cases
- A follow-up “policy registry” sweep mapped the space more systematically. Main
  result:
  - policy registry behaved as a stable V-sensitive lane (`A > B` broadly,
    improvements mostly low-dose V-only)
  - transform registry was noisier but exposed targeted K-sensitive wins,
    especially identifier/timezone transforms
- This was explicitly framed as a cheap prospecting tool for structure-search,
  not as benchmark-grade evidence.

Topic sensitivity probe by Codex:

  inside prompt contents where scientifically necessary.
- The probe combined ordinary completions, candidate continuation scoring,
  static J-lens prompt-token snapshots, and generation-trajectory scans across
  layers.
- Multiple execution/harness issues were found and fixed:
  - initial pod run stalled on unauthenticated HF model fetch
  - alignment bug: raw topic line token sequence did not survive chat-template
    rendering; graft alignment was changed to rendered prompt phrase tokens
  - missing `jlens` dependency on the pod
  - static prompt-token lens locator was too brittle for English phrase
    tokenization, so a cheap static-only repair run was added
  - a generic candidate-probability table was found misleading and replaced with
    case-specific continuation scoring

  - this looked less like generic “panic/refusal” and more like topic- and
    language-dependent narrative routing
  - Chinese direct prompt strongly preferred a reform/development redirect
  - English 1989 prompt preferred official/stability wording over direct factual
    continuation
  - June Fourth, Tank Man, and Kent State prompts preferred direct factual
    continuations
  - repaired static J-lens snapshots suggested sensitive associations were
    internally present at prompt tokens even when Chinese generation redirected
