# 2026-07-05 (UTC) — Daily Meta-Summary

_This was the busiest single day of the ValueGraft project to date: the 4B pilot
and its external-review amendments were absorbed, a mitigation-first reframing
was adopted and executed as a two-phase program, a full multi-scale (4B/30B)
results package was completed with tuned interventions, a public repo and paper
draft were started, extensive prior-art research was done, and a multi-pod cloud
campaign was launched to scale evaluation onto standard benchmarks and real
coding-agent traces._

## Main developments

- **Reframing from mechanism to mitigation.** External review (independent model
  critique, then a GPT-5.5 read-only session) converged on the same correction:
  "write-time KV state differs from re-encoded text" is close to self-evident
  and not itself a contribution. The user redirected the project's central
  question to mitigation-first: can a small, deployable cache-state intervention
  reduce the damage conversation compaction causes, in a way that survives
  negative controls and looks plausibly deployable? This reframing is now
  treated as settled and load-bearing for all subsequent writing — later in the
  day the user issued a further, stronger version of the same correction:
  "compaction destroys context-conditioned state" is not a finding at all, only
  an assumed baseline/denominator against which interventions are scored, and
  any document phrasing it as a result must be rewritten.
- **Two-phase execution.** Phase 1: close out the in-flight 30B run cleanly (no
  arm-matrix expansion), with STATE.md/DECISIONS.md/RESULTS.md brought current.
  Phase 2: one narrow, clean mitigation contrast — **H-pack vs B-min-pack**
  (later renamed for the paper to **ValueGraft-Pack vs FreshPack**) — identical
  packed summary tokens differing only in write-time vs fresh encoding, scored
  primarily on fabrication-vs-admission over unknowable items, with a
  wrong-summary donor control and referent/sense as secondary metrics.
- **External-review amendments absorbed into the harness:** a new **B-causal**
  control (removes a tail→summary ordering confound from arm C), negative
  controls (wrong-conversation and shuffled-value grafts) elevated to
  load-bearing rather than optional, a six-class leakage taxonomy applied
  retroactively, a GQA aggregation-rule decision for arm G (deferred), a new
  contradiction-probe category (deferred to phase 2/later), and a
  metric-hierarchy flip making probe accuracy (by category × leakage class) the
  headline over continuation NLL.
- **Second family of value-blending arm: ValueGraft (formerly
  "E-post/E-inter")**, tuned via an alpha sweep with a strict validation→holdout
  split, plus a **layer-profiling and per-head-profiling investigation** that
  found a real mid-depth layer band at 4B (L12–L22, peak L17) but a
  validated-null on per-head structure (holdout discipline caught what looked
  like a per-head effect but was a selection artifact — this null is now cited
  as evidence the holdout ritual works).
- **α>1 "value steering" discovery at 30B:** extrapolating past old values
  (α=1.0–1.5) outperformed blending, reframed via a classifier-free-guidance
  analogy and given fixed terminology (blending for α≤1, steering/extrapolation
  for α>1).
- **Standard-benchmark validation:** LongMemEval (a real long-conversation
  memory QA benchmark) was run at 4B and 30B, both as a ≤16K-token subsampled
  contrast and later (stage 1b) planned as the genuine full-haystack protocol on
  cloud hardware. Real coding-agent trajectories (SWE-Gym/OpenHands) were also
  evaluated as an offline next-action-prediction proxy.
- **Cloud scale-up.** A RunPod-based, prepaid, spend-capped multi-pod
  campcampaign was designed and launched (HF/transformers port of the MLX
  surgery code, validated via the same identity-test ladder) to run LongMemEval
  at full scale, SWE-Gym traces, and a second standard benchmark, with model
  diversity (Mistral, Llama-3.3-70B, Gemma) as a secondary, budget-permitting
  goal — a goal ordering the user corrected repeatedly away from an initial
  drift toward prioritizing new-model diversity.
- **Deployment/API framing work:** an "opaque compaction handle" design note (a
  `compact_from(boundary, instructions) -> {summary_text, compaction_token}`
  primitive, analogous to existing
  prompt-cache/session-handle/opaque-reasoning-token patterns) was written up as
  speculative deployment framing, not a design mandate. Later in the day, a
  substantial prior-art investigation found that OpenAI and Anthropic already
  ship adjacent opaque-compaction/prompt-caching primitives in production APIs —
  meaning the "opaque handle" idea is not novel, though no public evidence
  confirms any provider uses this project's specific value-tensor mechanism. The
  defensible novelty claim was narrowed to the summary-boundary value-state
  mitigation experiment and its evaluation.
- **Paper/repo drafting begun.** A public GitHub repo was created and the full
  history pushed; a wide draft and a tighter "focused" draft were written in an
  isolated `paper-working/` directory, with arms renamed for the paper
  (ValueGraft-Pack, FreshPack, ValueGraft-Blend) while leaving code/repo
  internals unchanged. A stricter git-staging protocol (never stage
  speculatively, always commit by explicit pathspec) was adopted given
  concurrent multi-agent activity in the repo.

## Terminology and methodological clarifications to persist

- **Claim-hierarchy discipline:** primary = mitigation (does a small
  intervention reduce compaction-induced errors on leakage-clean probes vs a
  text-summary baseline); secondary = mechanism (write-time value states carry
  context-conditioned information); boundary = limits/costs. Avoid language like
  "meaning lives in the values"; prefer "value states carry context-conditioned
  information useful for downstream interpretation."
- **Compaction damage is scaffolding, not a finding** — it is the assumed
  baseline/denominator, never to be reported as a novel result.
- **Arm naming (paper-facing) vs code-facing names differ by design**:
  H-pack/B-min-pack in code ↔ ValueGraft-Pack/FreshPack in the paper;
  E-post/E-inter ↔ ValueGraft-Blend (alpha ≤1 blending, alpha >1
  steering/extrapolation).
- **C vs B-causal, H vs B-min** are the two clean single-variable contrasts; C
  itself remains too confounded (old keys, gapped positions, different causal
  order) to carry the central claim.
- **Continuation NLL is secondary; probe accuracy by leakage class is the
  headline metric.**
- Holdout/validation-split discipline is now a hard requirement for any tuned
  parameter (alpha, layer band, head slot), demonstrated concretely by the
  per-head 4B null.
- Git-staging protocol: never `git add -A`/`.`, always explicit pathspecs, given
  concurrent multi-agent repo activity.

## Empirical results (with caveats — all pilot/early-cloud scale)

- **4B pilot (complete):** no probe-accuracy mitigation on leakage-clean probes
  (referent/sense unchanged vs baseline); but three independent, control-backed
  mechanism signals hold (H-gap beats B-min on continuation NLL by +0.093 nats;
  light value-grafting (α=0.25) reliably helps NLL; an isolated micro-experiment
  shows transplanted values carry word-sense margin). A strong, unplanned
  finding: write-time-encoded summary state (H-gap) makes the model admit
  ignorance about evicted facts far more than text-only compaction, which
  fabricates.
- **30B pilot:** the honesty/anti-fabrication effect strengthens with scale
  (near-total suppression); the deployable value-graft (E-post/ValueGraft-Blend,
  α=1) flips from harmful at 4B to net-positive at 30B (~29% gap closure); C
  shifts from harmful to roughly neutral. Effects are conditional — they vanish
  on free-form natural conversations that don't much depend on evicted content.
- **Phase 2 (H-pack/ValueGraft-Pack vs B-min-pack/FreshPack):** at both scales,
  the packed write-time-encoded arm dramatically suppresses fabrication vs
  production-style compaction; most of the gain is from the packed layout
  itself, but a write-time-encoding-specific component grows with scale (10→3
  fabrications at 30B vs negligible at 4B on the matched decoy pair).
  Referent/sense recall is not improved by packing — the intervention buys
  honesty, not memory.
- **Tuned ValueGraft alpha sweep (validation→holdout):** 4B optimum is mid-band
  α=0.25 (~10% gap closure); 30B optimum is a much larger α (0.75–1.25,
  including the steering regime) with ~24% gap closure and no layer-gating
  needed — a qualitatively different, scale-dependent optimum.
- **LongMemEval (standard benchmark):** compaction damage replicates strongly
  and universally (71–81% full-context accuracy collapsing to ≤11% under any
  compacted arm; recall of evicted facts is not recovered by any method tested).
  The honesty effect is frame-dependent: it replicates at 4B (~35% fabrication
  reduction) but nearly vanishes at 30B on this benchmark's personal-QA framing,
  because the larger model's refusal calibration already covers the gap —
  contrasted sharply with the project's own agentic synthetic corpus, where the
  30B baseline fabricates heavily and the intervention cuts it substantially.
  This yields an explicit scope statement: the honesty benefit applies to
  mid-task agentic compaction, not retrieval-style personal QA.
- **SWE-Gym coding-trace proxy (75 real OpenHands trajectories):** tuned
  ValueGraft recovers +0.0156 nats (45/75 wins, CI [0.005, 0.027]), roughly 10%
  of measured compaction damage — modest but statistically clean (d≈0.33,
  t≈2.8), accepted by the user as a legitimate result given the instrument is an
  unusually unforgiving off-policy lower bound. This result was treated as
  sufficient to make the end-to-end OpenHands+condenser follow-up "default-on"
  rather than contingent.
- **Negative controls throughout hold up:** shuffled and wrong-conversation
  grafts crater performance at both scales, and per-head/per-slot overfitting is
  reliably caught by the validation/holdout discipline.

## Outstanding risks and open questions

- Referent-recall recovery remains unsolved by every method at every scale — an
  honest, persistent null.
- The honesty effect's scope (agentic/working-context compaction vs
  retrieval-style QA) needs to be stated plainly in any write-up, not treated as
  a universal claim.
- A methodology inconsistency was flagged late in the day: comments in the
  serve-shim/full-LongMemEval-runner code describe summarizing only the
  evicted/older region, but the implementation appears to still summarize from
  the full message list before appending the tail — needs reconciliation before
  final reporting.
- The decisive real-world test — an end-to-end coding-agent task-performance run
  (E1, via an OpenAI-compatible serving shim with server-side
  compaction/ValueGraft) — was in progress but unresolved at day's end.
- Several operational hardening items from a cloud-stack code review remain
  open: atomic/resumable writes for long benchmark runs, ignoring generated
  pod-lifecycle state files, stronger LongMemEval scoring/aggregation for
  benchmark-scale claims, and an explicit audit of HF-vs-MLX H-gap suffix
  semantics.
- Repository disorganization was explicitly flagged by the user as needing a
  cleanup pass before any broader sharing, deliberately deferred to avoid
  disrupting running pipelines.
- Whether frontier-provider compaction APIs (OpenAI's encrypted compaction item,
  Anthropic's beta compaction block) use anything resembling this project's
  value-tensor mechanism remains unconfirmed; the novelty claim has been
  narrowed accordingly.
- Likely next actions: complete the in-progress cloud stages (full LongMemEval,
  SWE-Gym, a second standard benchmark), resolve the E1 end-to-end coding-agent
  run, reconcile the summarization-scope code/comment discrepancy, apply the
  pending operational hardening fixes, and continue the focused paper draft.
