# 2026-07-06 daily meta-summary

_The UTC day opened mid-overnight ValueGraft shift work (pod scale-out, matrix
tuning, honesty-suite bf16 replication), was disrupted by a shim session-leak
contamination discovery and a related task-source/provenance correction around
synthetic-vs-real task framing, and closed with the coding-agent evaluation

from SWE-bench entirely after the subject model floored on it, toward a

## Research and workflow developments

The night's matrix run (7 pods, dose-response and layer-config arms over
synthetic tasks) closed with a per-layer tuned config ("cfg=layers") as
provisional champion (9/9, guard-passed) and the 57-slot mask ("posslots")
formally killed by its wrong-conversation contamination guard. The bf16
honesty/fabrication finding from 4-bit pilots replicated closely at full
precision (write-time-KV arm: 17% decoy fabrication vs 83% for plain
compaction). A morning report and day-plan were committed before the user woke.

During the day, two serious process failures were found and fixed:

1. **Shim session-state leak**: sharing pods across arms let per-session
   summary/config state bleed across same-task-different-mode runs. Remediated
   with disjoint task-lane assignment, pre-flight isolation probes, and a harder
   self-tested task ("t3") that a brief summary cannot carry.
2. **Task-source/provenance correction**: despite language like "real agent" /
   "real coding tasks," all live-agent episodes had in fact been running on the
   synthetic harness for ~12 hours after standard SWE-bench tasks were first
   discussed, because the new real-task rows were appended to the end of
   already-long queues. The resulting process correction adopted a standing rule
   that every results statement must name its task source (synthetic vs.
   SWE-bench) inline.

A parallel adversarial pipeline audit (`PIPELINE-AUDIT.md`) found three critical
validity bugs, all fixed same-day: an asymmetric wall-clock timeout that let the
no-compaction oracle arm burn far more per-turn compute than compacted arms
(biasing _against_ the paper's own hypothesis), missing config-provenance fields
in score data, and a test-ID cleaning filter that could silently drop SWE-bench
pass/fail criteria for any instance, not just the one repo it was meant to
exclude.

Real-task evaluation then hit a capability floor: the 30B subject model failed
every SWE-bench-Lite/Verified attempt (5 straight full-capability oracle-mode
failures) even on human-rated "<15 min fix" instances, while a Sonnet subagent
solved the easiest instance in 52 seconds — confirming the floor was the subject
model, not task difficulty. This triggered an "A-first gating" redesign
(validate solvability with the uncompacted arm before spending compacted-arm
budget), a scaffold-configuration audit that found two silent misconfigurations
(disabled native tool-calling, hardcoded greedy decoding contradicting the model
card), and construction of a new chained-Exercism task tier as a
capability-appropriate fallback. A forensic autopsy of the first real-task
failure (`flask-5063`) found the premature self-termination was
compaction-shaped (a self-authored test-before-finishing plan was created once
and never resurfaced) while the wrong patch content was capability-shaped (the
agent never discovered the actual required behavior in the hidden tests).

Separately, a full day was spent on paper synthesis: two competing focused
drafts were produced reusing shared bibliography and structure, a
prior-art/hosted-API review (OpenAI Responses compaction, Anthropic/Gemini
analogues, KV-editability literature) was folded in to bound novelty claims, and
a scouting pass evaluated tau2-bench's `banking_knowledge` domain as a
standard-benchmark confirm-phase candidate offering a clean evictable-vs-
system-message policy dissociation.

## Decisions and terminology that should persist

- **ValueGraft** is now the umbrella name for the intervention family, with a
  two-axis `alpha_K`/`alpha_V` parameterization replacing the old ad hoc
  `A/B/E/H-pack` letter codes for reporting purposes (internal code/log
  identifiers are left unchanged for provenance). Named regions: Plain Summary
  Compaction (`alpha_K=0, alpha_V=0`), V-only Graft (`alpha_K=0`, current live
  coding arms), K-only Graft, KV-Graft, Coupled KV-Graft. `alpha=1` is not a
  separate method name ("Replace" was explicitly rejected as a label); it is
  just an endpoint of the continuous parameter.
- The historical `H-pack`/`B-min-pack` packed-summary arms are auxiliary
  evidence about write-time summary encoding, not clean instances of the current
  K/V taxonomy — they confound layout and tail-retention with state source and
  should never be described as a layout variant of the live V-only Graft arms.
- Canonical human-readable arm names for reporting: Original, Compacted,
  Compacted + value graft (α=0.75), Compacted + value graft (α=1.0), Compacted
  - layer-tuned value graft.
- A "model card as difficulty certificate" methodology rule was adopted:
  vendor-published benchmark standing is consulted as an external calibration
  reference before committing further internal empirical trial effort.
- Standing rules added this day: no new runs against an abandoned task family,
  even for "boundary documentation"; every results statement must name its task
  source inline; implausible results (anomalously clean or anomalously bad) must
  be inspected before being trusted; serving configuration must follow the model
  card unless a documented, logged deviation exists.

## Empirical results and observations

- **Honesty/fabrication (bf16, replicated)**: write-time-KV arm 17% decoy
  fabrication / 4% evicted-fact fabrication vs. plain compaction 83% / 29% —
  closely reproduces the earlier 4-bit finding.
- **Matrix champion (synthetic tasks, pre-contamination-fix)**: per-layer tuned
  config 9/9 including harder threshold tier, guard-passed; scalar α=0.75 showed
  an anomalous underperformance later substantially attributed to a serving bug
  rather than a real dose effect.
- **Clean synthetic re-run (post-fix)**: small-n but directionally favorable to
  V-only grafting over plain compaction (A 4/4, B 2/3, E:a0.75 4/4, E:a1.0 3/3),
  explicitly caveated as too small to support a conclusion.
- **Real SWE-bench tasks**: zero passes across all attempts under both plain and
  oracle-retrieval settings; treated as a capability-floor finding for the 30B
  model under this harness, not as arm-comparison evidence.
- **Chain-tier (Exercism-derived) tasks**: partial validation success (4/6
  chains), roughly matching the vendor-card-predicted capability band for
  repo-level vs. exercise-scale tasks.
- **Synthetic legacy/brief-summary benchmark** (non-production-faithful,
  supporting evidence only): A 13/13, B 5/12, E:a0.75 11/12, E:a1.0 3/3,
  E:cfg=layers 11/15.

All real-task and matrix numbers from this day should be treated as provisional:
several were generated before the session-leak fix, the summary-prompt fix, or
the pipeline-audit fixes landed, and are explicitly demoted to non-headline
strata in the project's own bookkeeping.

## Outstanding risks and open questions

- Whether the 30B subject model can pass _any_ real standard-benchmark coding
  task once serving misconfigurations (tool-calling, sampling) are corrected — a
  controlled A/B was launched but not resolved by day's end.
- Whether the chain-tier and/or tau2-bench `banking_knowledge` domain can supply
  enough real, standard, compaction-sensitive task volume to replace SWE-bench
  as the primary real-task evidence source; only a small pilot is authorized
  before further commitment.
- Whether the asymmetric-timeout fix and other pipeline-audit corrections change
  the shape of prior real-task results once re-run.
- A model-swap ladder (Qwen3-Coder-30B → Qwen3-235B → GLM-4.5-Air) remains
  catalogued but unexecuted, gated on chain-tier and scaffold-config fixes first
  failing to rescue the current model.
- Budget for further real-task/confirm-phase work is explicitly gated on the
  chain-tier arm table showing positive results.
