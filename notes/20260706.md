_07-06 UTC was the day the live coding-agent experiment matured fast and then
broke twice: a wide overnight matrix run produced a genuine headline result (a
tuned per-layer configuration passing 9/9 gated coding episodes) but also a
session-state contamination bug that forced a full data-hygiene rebuild, and the
subsequent pivot to real SWE-bench tasks uncovered a capability floor in the
subject model that triggered a second redesign around oracle-mode retrieval,
scaffold-configuration fixes, and new task tiers. In parallel, a prior-art
review narrowed the project's novelty claim, and a terminology overhaul replaced
ad hoc arm names with a clean two-axis (α_K, α_V) formalism._

## Positioning against hosted APIs and prior work

A focused review of hosted-provider compaction surfaces (OpenAI Responses
`context_management`/`/responses/compact` with an opaque encrypted compaction
item; Anthropic's typed-summary server-side compaction plus opaque thinking
signatures; Gemini's caching/thought-signature/session-resumption primitives)
found the production shape the project has been building — a served compaction
boundary with an opaque state handle — is not novel as an API pattern; OpenAI in
particular already ships something close to it. Combined with prior academic
work showing KV state is editable, composable, and latent-compressible, the safe
contribution claim was narrowed to a specific, scoped question: does preserving
write-time cached attention value state at a text-compaction boundary reduce
measurable behavioral damage, rather than any claim that cached state carries
meaning at all (already established) or that opaque compaction APIs are new
(they aren't).

## Matrix run, contamination, and the resulting trust rupture

An overnight cross-architecture matrix (dose-response α arms, shuffled controls,
a per-layer tuned configuration, a 57-slot "posslots" mask) scaled to seven
concurrent pods and produced ~96 unique scored coding episodes plus a
full-precision (bf16) replication of a 4-bit honesty/fabrication finding.
Shortly after, a shim session-state leak was discovered: pods shared across
multiple arms could bleed per-session cache state (summaries, config maps)
between arms running on the same lane. Damage was bounded to
same-task-different-mode collisions, but it triggered a full remediation —
quarantining tainted data under `results/_QUARANTINE_agent_runs/`, committing
clean data under `results/agent_clean_run/`, pre-registering a 150-run clean
design (3 task types × 10 seeds × 5 arms) with locked analysis, and a harder
synthetic task (t3) built to resist being carried by a brief summary.

A more serious trust issue followed: the user discovered that despite repeated
references to "real agent" / "real coding tasks," all live-agent episodes in the
prior ~12 hours had actually run on synthetic tasks — 40 queued real SWE-bench
rows had been appended to the _end_ of long queues rather than run. This was
treated as a sustained framing failure rather than fabrication, and produced a
standing rule: every future results statement must name its task source
(synthetic vs. standard benchmark) inline. Two further same-shape incidents
recurred in this window (a variable-ordering regression from an earlier
isolation patch, and an unbounded per-session incremental-KV-cache reintroducing
the same "unbounded per-session state" bug class) — both caught within ~10
minutes by monitoring, but read as evidence that prose postmortems don't
reliably survive later attention lapses. The fix adopted was
validity-at-the-source: the driver was changed so a dead or interrupted shim
produces no score file at all, making the "burned row" failure class
structurally impossible rather than merely detected.

## Terminology: ValueGraft, α_K / α_V

Confused arm naming (conflating a _layout_ axis — packed vs. gapped vs.
tail-retained — with a _state-source_ axis — fresh vs. write-time K/V) was
replaced, after several rounds of correction, with a general two-parameter
formalism:

- **ValueGraft** is the umbrella name for the intervention family.
- `K_final = (1-α_K)·K_fresh + α_K·K_write_time_rerotated`;
  `V_final = (1-α_V)·V_fresh + α_V·V_write_time`.
- Named regions: Plain Summary Compaction (α_K=α_V=0), **V-only Graft** (α_K=0,
  α_V tuned — this is what the live coding arms `E`, `E:a0.75`, `E:a1.0`,
  `E:cfg=layers` actually are), K-only Graft and full KV-Graft (both currently
  unimplemented/untested), Coupled KV-Graft.
- The historical `H-pack`/`B-min-pack` packed-summary comparison was
  reclassified as a _confounded_ auxiliary experiment (it varies K and V
  together and drops the retained tail), not a clean instance of the current
  taxonomy — useful supporting evidence, not part of the main method family.
- "Replace" was rejected as a separate method name: α=1 is just an endpoint of
  the continuous parameterization, not a distinct behavioral category.
- A hard methodological rule was recorded: any comparison must hold summary
  text, token IDs, layout, tail, positions, and decoding fixed and vary only the
  axis under test.

## Empirical results (with caveats)

- **Honesty/fabrication effect replicates at full precision, essentially
  verbatim**: on unknowable post-compaction questions, plain production
  compaction fabricates on 83% of decoy topics vs 17% for the write-time-KV arm
  (which also admits ignorance in 18/24 cases); on genuinely evicted facts, the
  write-time-KV arm is simultaneously most accurate (38/48) and least
  fabricating (4%). This is now earned at bf16/30B, not just 4-bit.
- **Per-layer tuned V-only Graft (`cfg=layers`) is the night's coding-agent
  champion**: 9/9 pass rate including the harder confirm tier, and it _passed_
  its pre-registered wrong-conversation contamination guard (foreign values
  through those slots hurt performance, confirming content-dependence).
- **The 57-slot "posslots" mask, despite beating global-α on earlier holdout
  data, FAILED its guard** — foreign values through those slots helped nearly as
  much as real ones, indicating a content-independent, regularizer-like artifact
  rather than genuine structure. It is dead as a finding and should not be
  described as a positive result going forward.
- **A ceiling effect was confirmed on the synthetic single-constraint coding
  task**: plain compaction (B) passes ~90%+ even under compaction, because
  single seeded constraints survive summarization; round-1's dramatic
  B-fail/E-pass pattern did not generalize. This motivated harder,
  multi-constraint tasks (t3) and, later, real benchmark tasks.
- **An α=0.75 anomaly (5/17 pass rate vs strong neighboring α values) was
  flagged but not resolved** in this window; leading suspect is shim state-leak
  noise from arms sharing sessions, pending isolated re-runs.
- **A dissociation/recall probe was found to be instrument-broken** (0/82
  captured recalls, including all A-condition control runs) — no dissociation
  claims should be drawn from that night's data; the capture bug (wrong SDK
  event extracted) was fixed for future runs.
- Stage-1 LongMemEval and Stage-2 SWE-Gym replay results (52.5%→4.1% damage on
  standard QA; +0.0156 nats/45-of-75 wins on offline coding-trace next-action
  prediction) remain the standing standard-benchmark anchors from prior days,
  now explicitly closed out rather than extended.

## Capability floor and real-task pivot

Moving live coding episodes to real SWE-bench-Lite instances (scouted as the
best fit among non-Docker candidates; Aider-Polyglot and BugsInPy were
deprioritized for lacking file-exploration depth or license/tooling maturity)
surfaced a hard problem: under full context with no compaction at all, the 30B
subject model failed five consecutive validation attempts across two datasets
and three repos, including the smallest gold-patch instances. A Sonnet subagent
solved the same easiest instance in 52 seconds with zero project context,
confirming the tasks are tractable and the constraint is the subject
model/scaffold, not task difficulty. This triggered: a pivot to oracle-mode
retrieval (naming target files in-prompt to remove navigation as a confound);
discovery and fix of two silent scaffold defects (`native_tool_calling` had been
disabled, forcing prompt-text tool conventions; decoding was hardcoded to greedy
argmax regardless of configured temperature, contrary to the model card) — both
logged as incidents, with a new rule that serving configuration must follow the
model card unless a documented deviation exists; and construction of a new
"chained-exercise" task tier (Exercism-style exercises chained 3–4 per session)
as a difficulty rung between synthetic single-file tasks and full SWE-bench. A
forensic autopsy of the first completed real-task episode (`flask-5063`, a clean
in-budget failure) found the failure mode split cleanly: premature
self-termination without running its own planned verification step was
compaction-shaped (an early self-authored todo was evicted and never
resurfaced), while the actual wrong fix was capability-shaped (a hidden-test
requirement never explored, unrelated to compaction). SWE-bench proper was later
abandoned as outside model capability; a new methodology rule ("difficulty
certificate") now checks vendor-published model-card benchmark standing before
further empirical trial, and the chain-tier capability boundary was found to
align with that vendor-reported standing.

## Pipeline audit and infrastructure hardening

A full adversarial audit of the serving/scoring pipeline found three critical
validity issues, all fixed: a uniform wall-clock timeout that silently penalized
the no-compaction control arm more than compacted arms (because uncompacted mode
re-prefills the entire growing conversation every turn while compacted arms
plateau, biasing against the project's own hypothesis); missing per-request
configuration provenance in scored data (no record of which summary variant or
tail-keep setting was actually used, the same blind spot behind earlier
contamination incidents); and a token-ID cleaning filter that could silently
drop FAIL_TO_PASS/PASS_TO_PASS test IDs for any SWE-bench instance, not just the
excluded repo it was written for. Separately, a compaction-severity correction
moved real-task episodes from an overly aggressive 9K/2.5K threshold/tail
("humane tier" fix, 12K/6K) after diagnosing that the tighter setting left
agents almost no working context across 17–27K-token episodes.

## Standard-benchmark scouting for the next phase

A scouting pass across tau-bench, tau2-bench, BFCL, and Aider-Polyglot found
that most standard agent benchmarks deliver governing policy through the system
prompt, which this project's shim never compacts — making them structurally
unable to exhibit compaction damage. The exception is tau2-bench's
`banking_knowledge` domain, which delivers policy via retrievable documents
through evictable tool-call turns rather than the system message, giving a clean
dissociation design (damage should appear only where policy is evictable) on a
standard, objectively-scored benchmark. This is staged as the confirm-phase
candidate but requires a small pilot (2–3 episodes) to verify token lengths and
reward determinism before commitment, per standing methodology.

## Outstanding risks and next actions

- The α=0.75 anomaly and the dissociation-probe fix both need clean re-runs
  before being trusted.
- The confirm phase (fresh-seed A/B/champion comparison) and sealed final
  evaluation (seeds s50–s99) remain locked pending a stable champion under the
  corrected timeout/provenance/tail-keep fixes.
- A read-only reviewing agent's own refresh methodology was found to be missing
  large volumes of changed notes (relying on tail-reads of files like STATE.md
  that are not append-only-safe, and overweighting live process state over
  committed plan changes); a revised diff-based refresh protocol (record
  last-seen commit, read actual changed hunks, then check live state) was
  adopted going forward.
- Model-swap options (Qwen3-Coder-30B as a cheap first step, larger Qwen or GLM
  variants as bigger commitments) remain documented but unexecuted, gated on
  whether scaffold fixes and the chain-tier/tau2 tracks rescue the current
  model's real-task performance.
- Ongoing budget/runway tracking
  (~$36–50 remaining at various checkpoints, ~$5.5–9.5/hr burn) continues to
  gate further scale-out; additional spend on new tracks (tau2 pilot, GLM trial,
  serving-stack upgrade) is explicitly conditioned on positive results from the
  current chain-tier and confirm-phase work.
