## Executive verdict

The repository does not support a general claim that naively re-injecting write-time value vectors improves semantic continuity after compaction. Correct aligned values are much less destructive than the current shuffled/random controls, but the controls are not matched to the treatment-delta magnitude or covariance, so this does not yet establish hidden-history content specificity. The most credible broad performance result is therefore a qualified bound/null for a particular mixed-source intervention, not a successful mitigation.

That said, the disk evidence is not as simple as the current README's “mostly null, one replicated positive” framing:

1. The current synthetic held-out result is a pooled average over two sharply different, non-native corpus sources. On c07–c12, whose assistant replies came from a 4-bit Qwen3-4B renderer, the per-layer champion is positive (+0.120 nats/token; six-conversation cluster CI approximately [+0.056,+0.181]). On c13–c24, whose conversations were authored by Claude-family agents, the same configuration is negative (−0.050; 12-conversation cluster CI approximately [−0.076,−0.028]). The pooled −0.003 null is real as an arithmetic average, but it is not a homogeneous null and its weighting is arbitrary. The paper's statement that these assistant replies were generated by the bf16 test model is contradicted by `data/synthetic/c07.json` through `c24.json`. Separately, three of four compression-sweep levels rebuild the supposed write-time states after a different request from the one used to generate the summary; only `realistic` is request-consistent.
2. The old brief-SWE-Gym scalar positive was measured twice on the same 75 trajectories, not independently replicated. The two test-retest estimates are +0.0156 and +0.0133, but a disjoint 98-trajectory sample gives −0.0017. Averaging the two repeated measurements per old trajectory and then pooling the 173 unique trajectories gives **+0.00532 nats/token, bootstrap 95% CI about [−0.0027,+0.0131]**: null.
3. The latest July 10 in-domain SWE-Gym tuning result is nonetheless promising. A champion selected on 41 tuning trajectories (layers 12–17 and 30–35, alpha 1.0) scores **+0.0117 [+0.0063,+0.0172]** versus the compacted baseline on 57 disjoint evaluation trajectories. But its paired advantage over the fixed scalar graft is only **+0.0041 [−0.0048,+0.0132]**. By the analysis script's own preregistered reading rule, tuning has not yet been shown to beat the scalar method. Applying this frozen champion to the original 75-trajectory pool is the appropriate independent replication and was not on disk at audit time.
4. The pre-registered architecture story was not confirmed. The QK-norm directional hypothesis is contradicted by Mistral's positive referent result despite no QK norm. The only within-Qwen dense/MoE pair is inconclusive on its pre-registered referent sign because the MoE positive did not reproduce in the banked render and the dense model's referent CI spans zero. No 16-model regression was completed; only four usable non-anchor model results are on disk.
5. No end-to-end coding-agent task-success benefit has been demonstrated. The clean chain tasks had a ceiling (Compacted 4/4), SWE-bench had a capability floor (all tested arms failed, including full context), and tau-banking was too short to create a meaningful compaction boundary. SWE-Gym is offline next-action prediction, not agent execution or resolve rate.

My confidence is high in the null/bounding conclusion for the exact tested scalar intervention and mixed synthetic target population, moderate that a task/domain-conditional effect exists, and low that any current positive would improve real coding-agent task success without a new end-to-end experiment.

## 2. The synthetic held-out experiment: the important provenance discrepancy

### What the paper says

README §2.3 states that the conversation-body assistant replies were generated in-context by the bf16 test model and that “we do not reuse replies written by another model.” README Appendix B identifies c07–c24 as the held-out set.

### What the files say

**Observed:** `data/synthetic/c07.json` through `c12.json` have `meta.model = mlx-community/Qwen3-4B-Instruct-2507-4bit`. Files c13–c15 and c22–c24 have `meta.author=sonnet`, c16–c18 `author=opus`, and c19–c21 `author=fable`. The champion design note explicitly says validation uses `SC_NATIVE_RENDER=0 SC_SELFGEN=1`: the 30B test model generates the compaction summary, but it does not generate the conversation body.

This is a blocking methods/provenance error under `METHODS-PROVENANCE-REQUIREMENTS.md`.

### Source-stratified recomputation

I grouped every saved trace by `conversation_id`, retaining the repository's plant weighting, and reran its conversation-cluster bootstrap procedure within each source block:

| Configuration | c07–c12: Qwen3-4B-rendered (6 conv) | c13–c24: Claude-authored (12 conv) | pooled paper value |
|---|---:|---:|---:|
| per-layer | **+0.120** CI ~[+0.056,+0.181] | **−0.050** CI ~[−0.076,−0.028] | −0.003 [−0.041,+0.043] |
| per-head | +0.071 [−0.031,+0.170] | −0.004 [−0.044,+0.038] | +0.017 [−0.027,+0.062] |
| intersection | **+0.114** [+0.035,+0.176] | **−0.033** [−0.067,−0.004] | +0.008 [−0.032,+0.052] |
| union | +0.064 [−0.026,+0.153] | **−0.041** [−0.080,−0.003] | −0.012 [−0.053,+0.034] |

These subgroup intervals are exploratory and only six clusters support the Qwen block. The source blocks also differ in length, authoring process, and plant construction, so source is not causally isolated. But the interaction is too large to omit.

The saved compression-sweep scores have the same interaction. Per-layer recovery for Qwen3-4B-rendered versus Claude-authored bodies is respectively: ultra +0.058 vs −0.063; brief +0.077 vs −0.067; medium +0.104 vs −0.075; realistic +0.146 vs −0.090. But code inspection shows that ultra/brief/medium generated the summary under a level-specific request and reconstructed the supposed write-time cache under the constant realistic request. Only the realistic pair (+0.146 vs −0.090) is interpretable as the intended intervention; the nominal flat severity result must not be used.

**Inference:** the cleanest reading is not “write-time values are universally redundant,” but “a configuration tuned on Qwen-family-rendered text does not generalize to a Claude-authored corpus and can reverse sign.” This is compatible with the earlier nativeness/source concerns. It may reflect model-family nativeness, corpus length, conversation construction, or overfitting to the c01–c06 Qwen-rendered tuning distribution; current data cannot separate them.

### In-domain champion

The July 10 run used Qwen/Qwen3-30B-A3B-Instruct-2507 at resolved revision `0d7cf...`, torch.bfloat16, A100, brief self-generated summaries. A deterministic hash split yielded 41 tune and 57 eval trajectories. Eight six-layer depth regions were profiled on tune; positive-mean regions R2 (L12–17) and R5 (L30–35) formed the fixed alpha=1.0 champion.

Held-out eval results from `src/analyze_swegym_tune.py`:

- scalar alpha=.75 vs B: +0.0076 [−0.0042,+0.0193], null;
- in-domain champion vs B: **+0.0117 [+0.0063,+0.0172]**, 44/57 positive;
- champion vs scalar: +0.0041 [−0.0048,+0.0132], null;
- champion discrete action-match vs B: −1.75pp [−8.8,+5.3], null.

Using all 98 rows gives champion vs B +0.0111 [+0.0069,+0.0153] and champion vs scalar +0.0128 with a positive CI, but this includes the 41 trajectories used to select the champion. It is not a held-out superiority test. Likewise, rerandomizing the full 98 into 200 post-selection half-splits does not create independent validation.

The alpha sweep tested five alphas. Alpha=.5 happens to clear zero on eval (+0.0079 [+0.0007,+0.0154]), but tune selected .25, whose eval CI spans zero. The isolated .5 result is not confirmatory after searching five alphas.

### Discrete next-action metric

On all 98 disjoint trajectories, scalar action-match is 56% versus B 49%, paired +7.14pp [+1.02,+14.29]. It was designed before the run and is worth reporting as a secondary signal. However, 84/98 targets use `str_replace_editor`; the scorer matches only tool, path, and editor command (`view`, `create`, `str_replace`) and ignores the edit's `old_str`/`new_str`. Thus “match” does not mean the edit content is correct. This is a coarse behavioral action-type/path proxy, not task success.

### Coding-agent conclusion

**Observed:** a task-domain-tuned configuration has one valid held-out positive against B on 57 trajectories, while the fixed scalar does not replicate across 173 unique trajectories and the champion has not beaten scalar head-to-head.  
**Inference:** this is the strongest reason not to call the entire project a complete null, but it is not yet a demonstrated method improvement. Freeze the champion and apply it to the untouched original 75. Then, if it replicates, run actual actions/tests on a capability-matched subset or measure a more complete action representation.

## 4. Statistical audit

### Estimator

Replacing the mean ratio with raw `lp_E-lp_B` was correct. It is paired, interpretable in nats/token, and avoids division by a noisy near-zero gap. One terminology correction: the repository repeatedly calls raw_EB “bounded.” It is not mathematically bounded; log probabilities are unbounded below and their difference can take any real value. It is merely much better behaved than the ratio.

### Inferential unit

- Synthetic plants share a conversation and summary, so conversation-clustered bootstrapping is the correct improvement over plant bootstrap. Current champion/compression results do this.
- The bootstrap remains conditional on one realized conversation/render. It does not include render/generation variance, which was empirically large enough to erase the earlier effect. Statements of uncertainty should say “conditional on these rendered conversations.” A two-level design with independent rerenders inside scaffold would be needed for unconditional inference.
- SWE-Gym uses one target turn per trajectory, so trajectory bootstrap is appropriate at the stored level. But result JSONs save only integer indices and token metadata, not repository/task IDs. I could not audit whether multiple trajectories share a repository/issue or whether clustering by repo is needed. This is a provenance omission.

### Bootstrap implementation

`bootstrap_ci_95_cluster` resamples whole conversations with replacement and pools their plants. That correctly estimates a plant-weighted mean under cluster resampling. With 12–24 clusters, percentile intervals are coarse and should not be treated as definitive hypothesis tests. The point estimate is plant-weighted; a conversation-weighted estimand would differ if plant counts vary, though counts here are fairly similar.

### Multiplicity and adaptivity

Nominal 95% CIs are unadjusted despite many categories, alphas, layer regions, head masks, compression levels, models, metrics, and repeated pivots. This does not invalidate a predeclared aggregate held-out comparison, but it makes isolated category/model positives exploratory. Specific risks:

- the original project searched many alpha/layer/head configurations before selecting champions;
- 192 head marginals and multiple derived masks were explored, although later held-out evaluation helps;
- six synthetic categories x four configurations x several placebos/compression levels create many opportunities for a nominal CI to exclude zero;
- five July 10 alphas were examined; only the tune-selected alpha's eval result is a clean selection-aware claim;
- cross-architecture work inspected multiple models/categories while hypotheses and inclusion rules evolved.

The report should emphasize prespecified aggregate held-out results and label all subgroup/category findings exploratory unless adjusted or independently replicated.

### Selection and stopping

The overall research program was highly adaptive. That is acceptable for exploration but prevents treating the final collection as one confirmatory study. `PREREGISTRATION.md` covers a late cross-architecture sign-map question, not the full project. Its key predictions were not confirmed, and subsequent pivots/champion/compression/SWE tuning are separate exploratory-to-held-out sequences. Each such sequence should have its own dated analysis plan and a single primary contrast.

## 6. Actual coding agents: what was learned and how to test properly

### Existing end-to-end results

- Clean chain table (`results/agent_clean_run/chain-*`): A, B, alpha=.75, and layer champion are 4/4; alpha=1 is 3/4. Because B is perfect, the experiment has no compaction damage to repair. It demonstrates that full-strength grafting can harm one task, not that tuning recovers lost performance.
- Clean SWE-bench-derived rows: all tested arms failed, and the full-context/oracle arm also failed across the validation set. This is a subject/scaffold capability floor, not evidence about grafting.
- tau-banking: natural sessions were too short; high thresholds never compacted, low thresholds evicted too little or entered an amputation regime. No valid treatment contrast resulted.

### A viable real-agent experiment

It is worth exploring only after choosing tasks where the base agent succeeds often enough and compaction measurably hurts. A credible design would:

1. Use a capable coding model/scaffold and its native tool-call format/settings; capability-smoke 20–30 candidate tasks under full context first.
2. Freeze tasks based only on full-context solvability. Require a real B-vs-A damage gate before any E comparison.
3. Use production-faithful summary+tail compaction, with observed 2–6 true recompactions and saved summaries/cache artifacts.
4. Randomize or counterbalance A/B/E by task and seed; use matched seeds/tool environment; blind task scoring.
5. Primary outcome: tests/resolve rate with paired task-level analysis. Secondary: steps, repeated failed actions, and next-action logprob. Do not promote a proxy if task success is null.
6. Use one frozen graft (the July 10 in-domain champion is the current candidate), plus B and a source-shuffled placebo. No alpha search on evaluation tasks.
7. Cluster uncertainty by base issue/repository when multiple trajectories come from the same task family. Bank every trajectory and render.

If an affordable model still has low full-context resolve rate or B≈A, stop: that benchmark cannot answer the causal question. Offline SWE-Gym remains useful for cheap screening, but it is not a substitute for task success.

## 8. What the disk truly supports

### High confidence

- The cache surgery is not a no-op: alpha=0 and identity tests pass, real grafts change outputs, and correct values systematically outperform strong wrong-value placebos for sufficiently broad grafts.
- Wrong/random value injection can be very harmful; much of “content specificity” is avoidance of placebo harm rather than improvement over B.
- A flat value graft does not robustly beat plain compaction across the synthetic mixed corpus, compression levels, or 173 unique SWE-Gym trajectories.
- Full-strength/broad grafts can harm, and transfer across corpus/model is unreliable.
- The early 4-bit sense/referent recovery headline was render-fragile and does not support a stable positive claim.

### Moderate confidence

- There is a real interaction with corpus/domain/source. Qwen-family-rendered synthetic text and coding trajectories can show positive cells, while Claude-authored synthetic text and several other model/corpus combinations are null or negative.
- The July 10 in-domain SWE champion may produce a small improvement in next-action logprob under brief compaction, but independent pool confirmation is still required.
- Production-faithful longer summaries eliminate the observed scalar coding effect on the original 75.

### Not established

- Improved downstream coding-agent success.
- A general semantic-continuity recovery effect.
- A causal role for QK norm, MoE, dense architecture, keys, or a specific layer band across models.
- That self-generated summaries or model-native conversation bodies are universally required (they are plausible scope variables with suggestive interactions, not yet cleanly factorialized).
- Publication-grade generalization beyond this checkpoint, corpus construction, and proxy metric.

## 9. Highest-value remaining empirical work

1. **Finish the frozen July 10 champion confirmation on the original 75** without retuning. Report champion−B and champion−scalar; do not count the two old scalar renders as independent.
2. **Factorialize corpus provenance** on the same model: test model-native 30B bodies, same-family 4B bodies, and Claude-authored bodies with identical scaffolds/plants and multiple independent renders. This directly resolves the largest source interaction and fixes the README methods claim.
3. **If the champion replicates, run a small capability-matched real agent study** with resolve rate as primary. If it does not, close the mitigation claim as null/bounded.
4. **Re-run only the load-bearing cross-arch points under one final gate**, with born-annotated dtype/revision and banked renders, if an architecture claim remains desired. Do not attempt a 5-predictor regression with four to six models.
5. **Use hierarchical/repository-aware analysis for SWE-Gym** after preserving task/repo identifiers in every result.

## Bottom line for an advisor

The project eventually built enough controls to answer an important part of the original question: write-time values do contain content-aligned state that re-encoding does not reproduce identically, but naive grafting of that state is not reliably useful over text compaction and often harms out of distribution. That is a defensible negative result.

The remaining uncertainty is not “maybe the old headline was secretly right.” It is more specific: a small, domain/source-conditional effect may exist, and the July 10 coding champion is the first reasonably disciplined hint. One frozen replication plus one properly capability-matched end-to-end study would settle whether that hint deserves to survive as a positive result. Until then, the honest paper is a cautionary/bounding paper with a prominent source-interaction and a pending coding-domain exception—not a clean universal null and not a successful mitigation.
