_This shard covers autonomous execution of a local (MacBook/MLX)
semantic-continuity compaction experiment from initial setup through two major
refocusing pivots, culminating in approval and early execution of a cloud
(RunPod A100) scale-up phase._

## Initial setup and local pipeline (Arms A–E)

The assistant (Claude Fable 5) was directed to autonomously drive a pre-written
experiment brief testing whether write-time KV-cache state, discarded during
conversation compaction, carries recoverable meaning. Environment setup required
pinning `transformers` below 5.x for `mlx-lm` compatibility. The assistant built
a full arm ladder (identity tests L0–L4, then L5 full pipeline) covering: Arm A
(oracle full context), B (text-only summary compaction), C (gapped KV
retention), D (no-summary ablation), E-post/E-inter (value transplantation with
α sweep). All identity/null tests passed bit-identically or within tight
tolerance, catching three real bugs (batched-vs-single-token kernel mismatch, an
unstable `<think>` chat-template block, and a difflib alignment failure from
summary/tail ordering swaps).

Synthetic (12) and natural (8) conversation corpora were authored by Claude
subagents with 120 planted probes (referent, sense-disambiguation, stance,
ruled-out, evicted-fact categories); dialogue text itself was generated by the
local subject model (Qwen3-4B, later 30B-A3B) to preserve teacher-forcing
validity for the continuation-NLL metric. A contamination repair pass fixed
tail-leaking plants (77→115/120 clean). Judging was moved from the local model
to Claude subagents (first considered Haiku, then fixed to Sonnet per user
instruction — Haiku barred entirely for judging/meta-work) to improve quality;
dialogue generation itself stayed on the local subject model for experimental
validity (teacher-forcing requires text near-modal for Arm A).

## Operational lessons established early (durable rules)

- Always `tee` long-running command output to a scratch file before piping
  through `tail`/`grep`, to keep the full stream reviewable.
- Bracket long commands with wall-clock timestamps to catch pathological
  runtimes.
- When two GPU-bound jobs would each run ~2x slower in parallel, run them
  serially instead — no throughput gain, added memory risk.
- Verify process kills by PID, not by pattern (`pkill -f` patterns can miss
  argv-based duplicates) — this was learned the hard way (see incident below).
- Commit frequently at each milestone; avoid large binaries (weights live
  outside the repo).
- Maintain STATE.md (volatile snapshot, updated at each phase transition),
  DECISIONS.md (methodology/runtime deviations and rationale), and AGENTS.md
  (stable rules/traps) so a fresh session or agent can pick up work cold.

## Early findings (4B, local)

A micro-experiment showed transplanted value vectors alone carry word-sense
disambiguation (+0.8 nats at α=1 vs oracle +3.8). Full 4B pipeline results (with
H-gap/B-min added mid-flight, since they're nearly free with existing machinery)
showed: E-post α=0.25 reliably positive on continuation NLL on both synthetic
and natural corpora; heavier transplantation (α=1, E-inter) hurts monotonically;
C (gapped retention) mildly negative; H-gap beat its matched control B-min (same
summary text, encoded with vs without history) — the single sharpest test of the
core hypothesis, and it came out positive (~10/12 conversations at 4B).

## First external-review amendment cycle

A companion document (`amendments-from-external-review.md`) was reviewed and
largely adopted: added B-causal control (matches C's causal ordering to remove a
summary-vs-tail confound), negative controls (wrong-conversation graft,
shuffled-value graft), a six-class leakage classifier, contradiction probes, a
metric-hierarchy flip (probe accuracy as headline, continuation NLL secondary),
and a "brief/shadow" terse-summary condition designed to eliminate leakage so
probe comparisons carry full discriminative power. Judging for ~2,089 items at
4B was fanned out to Sonnet subagents in small batches (2 concurrent) rather
than run locally.

Full 4B results (post-judging): negative controls confirmed effects are
content/alignment-specific (catastrophic degradation); the brief/shadow
condition made the honesty effect visible — retained-state arms (D, H-gap, low-α
E) tend to admit ignorance on evicted facts where B confidently fabricates, an
emergent finding judged as potentially the most deployment-relevant result.

## Major pivot 1: mitigation-first refocusing

A user-relayed second-model critique (`refocusing-and-reframing.md`) argued the
original framing ("does write-time KV state contain meaning?") was closer to a
tautological mechanism question, and that the valuable question was whether a
small, deployable cache-state intervention reduces compaction damage relative to
text-only summarization. The assistant endorsed this assessment. The user then
explicitly directed a two-phase restructuring:

- **Phase 1**: bring the in-flight 30B run to a clean, interpretable stopping
  point (no expanding the old arm matrix) and sync STATE/DECISIONS/RESULTS.
- **Phase 2**: design one narrow, clean mitigation contrast rather than a wide
  arm sweep, with explicit success criteria (B fails vs A; a small intervention
  beats B; the gain isn't explained by leakage/wrong-conversation/shuffled
  grafts/generic fluency; the method is plausibly deployable).

The assistant chose **H-pack vs B-min-pack** (identical packed summary
tokens/positions, differing only in write-time vs fresh encoding) as the primary
Phase 2 contrast, scored on a purpose-built v2 probe set emphasizing
fabrication-vs-admission plus reference resolution, with a wrong-summary donor
control. This required a validated key re-rotation utility (RoPE convention had
to be reverse-engineered against MLX's own implementation; discovered that 4-bit
matmul kernels are sequence-length-dependent, creating a measurable noise
floor).

## 30B run and scale findings

While Phase 2 machinery was built, the trimmed 30B chain
(A/B/C/D/H-gap/B-min/E-post α∈{0.25,1}, both summary conditions) completed. Key
scale-dependent results:

- H-gap beat B-min in **12/12** synthetic conversations at 30B (+0.128 nats, CI
  [0.097, 0.158]), a _stronger_ effect than at 4B (+0.093–0.126) — the encoding
  advantage grows with scale.
- The α dose-response **inverted at scale**: at 4B heavy grafting (α=1) hurt; at
  30B, α=1.0 beat B (+0.052, ~29% of A−B gap closed) and even α=1.25
  (extrapolation) won in early per-layer profiling — the larger model tolerates
  K/V decoupling far better.
- C (gapped retention) went from harmful at 4B to roughly neutral at 30B.
- On **natural conversations**, none of the synthetic contrasts replicated at
  30B — the A−B gap itself was small (0.07 nats vs 0.18 synthetic), indicating
  these free-form dialogues didn't depend much on evicted content. This
  established the key boundary condition: interventions help in proportion to
  how much the continuation genuinely depends on evicted material.
- The user redirected away from further "redefining the claim" discussion toward
  concrete improvement work once in-flight runs closed out.

Phase 1 was closed with a committed addendum. Phase 2 then ran at both scales
with judging: packed write-time summaries substantially reduced post-compaction
fabrication, especially pronounced/near-total at 30B.

## Fine-grained α tuning and per-layer profiling

Per a suggestion to narrow the α grid around the low end (0.00–0.35) with a
validation/holdout split, the assistant ran disciplined sweeps: 4B optimum was
mid-band α=0.25 layers-gated (~10% gap closure, holdout-validated, CI excludes
0); 30B favored much higher α (up to 1.25, extrapolation past original values),
a qualitatively different regime from 4B.

Following a user-shared note on per-layer/per-head blending, a full per-layer
graft profile was run (36 layers × 20 conversations at 4B). It revealed a
consistent mid-depth "hump" (best layers clustering at L17–L22 of 36) with late
layers actively harmful, holding across nearly all conversations. A
validation-derived layer-selection rule (threshold-based, ~2 degrees of freedom,
not per-layer fitting) was evaluated on holdout and tied the hand-tuned mid-band
champion (+0.0182 vs +0.0173) — validating the _procedure_ (automatic layer
calibration) as something to test for cross-model transfer on rented hardware,
rather than shipping fixed magic layer numbers.

## Naming and positioning

Techniques were named for the write-up: **ValueGraft** (value-state
transplantation family), **SelfGist** (H-arm: self-generated, in-context-encoded
summary retained as training-free gist tokens), **SoftGraft** (deferred Arm G,
retrieval-weighted grafting). A literature search (properly executed, 30
fetches) found no exact prior work; closest neighbors (SamKV, "Models Take Notes
at Prefill," Compressed Context Memory) each miss at least one leg of the
combination. The public-facing document form was reframed from a formal
academic-paper voice to a community-blog-style technical report with explicit
provenance disclosure (Claude Fable 5 as primary designer/executor, GPT-5.5 for
adversarial review, user directing/verifying), findability-optimized language,
and a plain "is this known, or is it trivial?" framing. Provenance line:
"Anthropic Claude Fable 5 with some help from OpenAI GPT-5.5."

## LongMemEval and an operational incident

The assistant ran a real, standard benchmark (LongMemEval, subsampled to
≤16K-token instances with answer-bearing sessions placed in the evicted region)
at both scales, locally. Key results: compaction damage replicates strongly
(full-context accuracy 71–81% collapsing to ≤11% under any compacted arm —
recall of evicted facts remains an unsolved null under every method tested); the
honesty/fabrication-reduction effect held clearly at 4B (35% less fabrication
under H-pack) but flattened at 30B because the benchmark's personal-QA framing
already triggers refusal behavior, removing fabrication headroom — indicating
the effect is most relevant to agentic/mid-task framings, not retrieval-style
QA.

During the 30B LongMemEval batch, a `pkill -f` pattern-based kill left duplicate
model instances thrashing swap for roughly three hours undetected (user
explicitly voiced dissatisfaction with the delay and required a fix). Root cause
diagnosed and fixed; two standing watchdogs were added: a progress-based
stall/crash detector (keyed on new result files, not PID) and a periodic
memory-pressure monitor (alerts below 15% free or >25GB swap). This produced the
durable "verify kills by PID" memory rule.

An important methodological clarification was made to the user: the LongMemEval
runs are **not** comparable to published LongMemEval leaderboard numbers, since
the protocol was modified (subsampled ≤16K contexts instead of full ~115K-token
haystacks, custom evicted-region placement, contrast-based arm comparison rather
than the benchmark's standard judging prompts). The 30B model's 262K context
window makes the _actual_ standard protocol newly feasible on rented hardware,
proposed as a follow-on "stage 1b" pending approval.

## Overhead/deployability framing added to the write-up

In response to user prompts, the assistant quantified practical deployment
overhead: per-token KV cache (~96KB/token at 30B, ~144KB/token at 4B); a
SelfGist blob (terse summary + sinks) is roughly 8MB at 30B (up to 56MB for a
thorough summary), versus ~0.5KB for the raw summary text and ~1.2GB for the
full context's KV — comparable to shipping an image. ValueGraft, by contrast,
requires the entire old cache resident at compaction time and is inherently a
server-side/local technique, not a stateless-API-compatible request blob. The
user's own framing note (`opaque-compaction-handle-notes.md`) was adopted:
describe this via a handle lifecycle and split cost accounting (near-nil client
bandwidth, provider-side storage in the tens of MiB with cache-style expiry).

## Major pivot 2: cloud-plan restructuring toward standard benchmarks and power, not model variety

The user twice corrected drift in the assistant's cloud-scaling proposals. First
correction: rejected using Llama-3.3-70B as the default second-model choice
reflexively; the assistant clarified the real architectural reason
(Llama-3.3-70B is the newest architecturally "clean" dense model with vanilla
GQA+RoPE — many newer open models use MLA, iRoPE, or sliding-window hybrids
incompatible with the K/V-based surgery), and proposed Mistral Small 3.2 as a
better second-family choice, keeping Llama-3.3-70B only as an optional
dense-scale anchor.

Second, sharper correction: the user clarified that the purpose of renting
hardware was **not** primarily to test different models, but to (a) scale up
statistical power/data volume and (b) validate against established,
industry-standard benchmarks/datasets rather than homemade synthetic material,
on the model already best understood (Qwen3, which the user considers superior
to Llama and worth testing "at least as much" as new models). The assistant
explicitly acknowledged this as a correction to real planning drift and
restructured the cloud plan: standard-benchmark stages (full-scale LongMemEval,
then SWE-Gym/OpenHands real coding-agent trajectories, then a second published
benchmark such as LoCoMo or SCBench) now come first and are prioritized above
homemade probe corpora (demoted to a small stage 4) and above model-family
diversity (demoted to bonus stages 5–6, with Gemma 3 27B kept as a contingent
hybrid-attention profiling test and Llama-3.3-70B as the most
dispensable/expensive option).

Architectural scope was also clarified: the per-layer/per-head profiling
approach generalizes gracefully to models with ordinary per-layer K/V caches (it
empirically discovers where grafting helps rather than assuming uniform value),
including hybrid sliding-window/global-attention models like Gemma 3, where the
prediction is that graftable signal should concentrate in the sparse
global-attention layers. The one true architectural blocker is MLA-style caching
(DeepSeek-family), which has no separable V tensor to graft.

## Hardware/cost strategy and credentials

Hardware choice: a single A100 80GB pod, one at a time, serial
provisioning/run/terminate cycle (near-zero idle billing), chosen because
Qwen3-30B-A3B in bf16 fits comfortably (~61GB weights) and the workload is
memory-bandwidth-bound rather than compute-bound, making an H100 poor value.
RunPod was selected with a prepaid-credit hard cap as the spend guardrail.
HuggingFace and RunPod API keys were added by the user, immediately gitignored
and permission-locked, and held unused pending explicit go-ahead. Gating check
confirmed Qwen3-30B-A3B, Mistral variants, and both target datasets are ungated;
Gemma 3 27B was already user-approved; Llama-3.3-70B access was pending and was
approved by the user mid-session. Initial budget was $50 with an explicit
user-set trigger for a further $100 contingent on the core stages showing strong
results and the assistant's recommendation plus fresh user agreement; the user
later added the second $50 immediately (bringing committed budget to $100) to
avoid needing to compromise on the full plan, while keeping the further $100
decision gated on results.

## Cloud execution status at shard boundary

The assistant ported the surgery core to HuggingFace `transformers`/CUDA (full
identity ladder re-validated and passing on the new stack) before spending any
cloud money, per its "no debugging on the clock" discipline. A pod was
provisioned; stage 0 (bootstrap, model download, identity ladder on CUDA)
completed successfully
(~$0.35 spent). A symlink-vs-real-file rsync bug was caught and fixed (`-L` flag) before it could silently corrupt cached weights. A 2-question smoke test measured ~120s/question on the pod, prompting the assistant to cap stage 1 at 350 of the full 500 LongMemEval questions to protect budget for later stages (revised estimate ~$16
for stage 1 vs. ~$23 for the full 500). Stage 1 (350-question LongMemEval batch
across all six question types, all six arms, on Qwen3-30B-A3B in bf16) was
launched detached with a 30-minute watchdog cadence, ETA roughly 12 hours, and
was still running as of the shard boundary. Partial/live results at 5 questions
were explicitly flagged as too noisy to interpret. Coordination documents
(`cloud-plan.md`, `STATE.md`, `DECISIONS.md`, `AGENTS.md`) were kept current
with each pivot so a new agent could resume cold.

The shard ends with the user asking the assistant to **consider** (not yet act
on) whether parallelizing tests could speed up completion of the overall cloud
test plan without materially increasing total cost — a question left open for
the next shard.
