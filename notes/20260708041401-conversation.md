## Shard 1.

This shard covers the project’s setup, the first full experimental wave, a major
conceptual pivot, and the first mitigation-focused follow-on work.

Mainline arc:

- `claude-code` began by reading the brief, validating the local MLX/Qwen setup,
  and building the experiment machinery plus the L0-L4 identity ladder. Several
  silent-failure bugs were caught early and became standing methodology
  constraints: batched-vs-stepwise kernel mismatch, Qwen chat-template
  instability from an empty `<think>` block, alignment failure from summary/tail
  reordering, and Python/stdout buffering hiding progress.
- The user repeatedly requested operational discipline that later became repo
  policy: serial GPU use only, detach long jobs, mark the start/end of long
  commands, tee logs before tailing, and commit frequently. The agent agreed and
  later codified these into `AGENTS.md`/`STATE.md`/`DECISIONS.md`.
- Early substantive signal came before the full batch: a micro word-sense
  experiment showed transplanted values shifted disambiguation toward the
  planted sense; a toy conversation gave the expected arm ordering. This
  established “mechanism exists” before corpus-scale evaluation.

Experimental design and methodology changes:

- The original arm set A/B/C/D/E was implemented, then H-gap and B-min were
  added before the big run because they were cheap and gave a sharper test: same
  summary text with vs without in-context-written summary state.
- The scoring pipeline was changed in response to both the user and later
  external review:
  - judging moved off the local subject model to Claude/Sonnet;
  - continuation NLL was demoted to a secondary metric;
  - leakage classes and paraphrase checks were added;
  - B-causal and negative graft controls were added;
  - a brief/terse summary condition was added because standard summaries leaked
    too much planted information.
- A key division-of-labor principle was established and defended: the local
  model should generate conversation text only when that text becomes the
  held-out continuation under evaluation; scenario writing, judging, reviews,
  and meta-analysis should use Claude/Sonnet instead.

Corpus and data issues:

- Synthetic conversations and natural conversations were generated separately.
  The synthetic set was explicitly built so tail behavior depended on evicted
  middle context.
- A contamination audit found many planted facts leaking into the tail; a
  repair/resampling pass raised cleanliness from 77/120 to 115/120, with the
  remaining 5 classified as harmless early-section leaks because that early
  region was evicted anyway.
- Standard summaries often reproduced planted facts, especially on “evicted
  fact” probes, which made many nominal probe results untrustworthy. This became
  one of the central interpretive facts of the project and motivated the
  brief-condition runs.

4B-scale results and interpretation:

- At 4B, the continuation story was weak/mixed:
  - low-alpha `E-post` helped slightly and consistently;
  - heavier grafting hurt monotonically;
  - `C` (gapped retention) was mildly negative or null on NLL;
  - `H-gap > B-min` was positive on synthetic continuation NLL.
- Probe scoring under the standard summary condition was heavily
  leakage-swamped, so the judged brief-condition tables became the important
  evidence.
- A notable 4B qualitative pattern emerged from judged probes: retained-state
  arms, especially H-family/packed-summary variants and low-alpha grafts, more
  often admitted ignorance where B fabricated specifics. This “honesty/admission
  vs fabrication” effect became more interesting than raw answer recovery.
- Some categories were recognized as poor headline material: stance/ruled-out
  had ceiling/artifact problems, and some plants were all-fail because the gold
  answer demanded provenance detail no arm gave.

Conceptual pivot:

- A `codex`/GPT-5.5 read-only review and later user reflection produced a major
  reframing: the interesting question is not “does write-time KV state contain
  meaning?” but “can a small practical cache-state intervention reduce
  compaction damage?”
- `codex` authored `refocusing-and-reframing.md`, and `claude-code` endorsed it.
  Important consequences:
  - `C` was demoted from central practical claim to diagnostic/mechanistic
    evidence;
  - H-pack / SelfGist-style packed write-time summary state became the cleanest
    mitigation target;
  - low-alpha `E-post` became the practical value-graft path;
  - probes should be redesigned for mitigation sensitivity, not generic context
    dependence.
- The user explicitly instructed a two-phase plan: finish the smallest coherent
  chunk already underway, then redesign around mitigation. `claude-code`
  interpreted the in-flight 30B targeted run as that “smallest coherent chunk”
  because it already contained the mitigation-relevant arms and brief condition.

30B-scale shift:

- The 30B ladder initially appeared to pass implausibly fast, prompting
  skepticism and verification before trusting it; after verification the 30B
  targeted run proceeded.
- Partial and then full 30B synthetic results materially changed the picture:
  - `H-gap > B-min` became strong and universal on synthetic continuation NLL;
  - full-strength `E-post alpha=1` no longer hurt and instead beat B;
  - `C` moved from harmful toward neutral;
  - negative controls still cratered, supporting specificity.
- Natural conversations at 30B did not replicate the synthetic continuation
  gains because the A-B compaction gap itself was tiny there. This produced an
  important boundary claim: interventions only help when the continuation
  actually depends on evicted context.
- After Sonnet judging, the project treated Phase 1 as closed: write-time cache
  state appeared to suppress post-compaction fabrication strongly at 30B, while
  tuned value graft became net-positive at scale.

Mitigation-focused Phase 2:

- `claude-code` then built a narrower mitigation experiment centered on H-pack
  vs B-min-pack, with fabrication-vs-admission as the primary metric and
  referent/sense secondary.
- This required new machinery: key re-rotation for packed summary KV, new
  identity tests, and decoy probes audited to ensure the decoys had never
  appeared in the original conversations.
- An important runtime fact was learned while building this: 4-bit matmul
  kernels were sequence-length-dependent enough to create a measurable noise
  floor, so same-shape comparisons mattered.
- Phase 2 was run at 4B and then replicated at 30B, with Sonnet judging. The
  narrative emerging by the end of the shard was:
  - packed write-time summary state sharply reduced
    fabrication/admitted-missing-information after compaction;
  - this looked plausibly deployable because it only required retaining a tiny
    summary KV blob, not the whole old cache.

Alpha tuning / adaptive blending:

- The user proposed a finer alpha sweep focused on low doses and asked for
  validation/holdout discipline. `claude-code` queued and later executed this.
- Results diverged by scale:
  - 4B preferred a gated/mid-band low alpha (`alpha≈0.25`) with small but
    consistent holdout gains;
  - 30B appeared to prefer much stronger blending, even extrapolating past 1.0
    (`alpha=1.25` emerging as a winner during the run).
- Separately, `codex` suggested adaptive blending as a future refinement:
  per-token/head/layer gating based on match confidence or attention sharpness,
  not a single global alpha. This was explicitly noted as not yet implemented in
  the current pilot, but conceptually aligned with planned SoftGraft/G-style
  work.

Operational/handoff context:

- `STATE.md`, `DECISIONS.md`, and later `AGENTS.md` were created specifically so
  another session/agent could resume cleanly. The user repeatedly emphasized
  that state docs must stay current.
- A second-agent convention was normalized: Codex could add new files or review,
  while the main Claude loop continued the main experiment.
- By the end of the shard, the old matrix had effectively been superseded by a
  mitigation-first storyline: mechanism demonstrated, mitigation signal stronger
  at 30B than 4B, fabrication reduction more robust than recall recovery, and
  future work oriented toward deployable packed-summary state, tuned grafting,
  standard datasets, and possibly coding-agent traces.

## Shard 2.

This shard covers the transition from local Qwen work into a cloud-scale plan,
plus a new mechanistic line of investigation: per-layer profiling of ValueGraft.

Claude-Fable-5 reports that the 30B benchmark batch finished and was judged.
Main conclusion: LongMemEval reproduces the core compaction damage strongly, but
the “honesty”/fabrication reduction effect appears bounded by task framing. On
4B, the H-pack intervention reduced fabrication substantially; on 30B
LongMemEval’s personal-QA framing already triggers refusal behavior, leaving
little fabrication headroom. The intended write-up framing becomes: the
intervention matters more in mid-task agentic settings than in retrieval-style
QA. Claude also reports a real operational incident honestly: an earlier bad
kill pattern left two 30B instances thrashing swap for hours. In response, it
added persistent watchdogs for both progress stalls and memory pressure and
treated that as a lesson about monitoring long resident models.

The user points Claude to `per-head-alpha-speculation.md`, prompting a profiling
run across all 36 layers on 20 conversations. Early results repeatedly show the
strongest single-layer gains in a narrow mid-band, especially layers 17-22, with
one layer recovering about a third of the full tuned graft’s gain on a sample
conversation. This leads to an important methodological pivot: rather than
hand-tuning by model-wide alpha alone, derive a simple rule from validation data
that identifies “graft-friendly” layers, then test that rule on holdout. Claude
explicitly rejects unconstrained per-layer fitting as overfitting risk and
proposes a low-degree-of-freedom procedure: compute mean per-layer deltas on
validation only, threshold to choose layers, then test alpha 1.0 vs 0.75 on
holdout.

After the full profile completes, the holdout result is that profile-derived
layers with alpha 0.75 score about +0.0182 on 8/10 holdout conversations,
essentially tying the hand-tuned mid-band baseline at about +0.0173, while full
replacement remains too strong and slightly harmful. The interpretation is not
“automatic tuning beats manual tuning,” but that the automatic calibration
procedure successfully reconstructs the same structure manual sweeping had
found. That makes it a defensible transfer recipe for new models: calibrate
once, then graft only the positive layers. Claude distills the mechanism claim
as a mid-depth hump (roughly L12-L22, peaking around L17) with late layers
actively harmful.

The shard also captures cloud-planning and model-selection reasoning. Claude
proposes a RunPod-based plan with prepaid credits to bound cost, and says the
technical blocker is gone because the surgery core has been ported to Hugging
Face Transformers and passes the identity ladder locally. The user asks whether
a Hugging Face key is needed; Claude says yes for gated Llama downloads and
secondarily for avoiding rate-limit friction. After the user adds a HF key file,
Claude verifies the key files are protected, gitignored, and will remain unused
until explicit approval.

There is a substantive architecture discussion. The user questions why Llama is
being chosen if it is old. Claude’s answer is that model choice is driven by
architectural compatibility, not novelty: the experiment brief assumes standard
dense attention with conventional RoPE and ordinary per-layer K/V caches. Claude
argues that many newer families violate those assumptions in ways that would
confound replication: Llama 4 with iRoPE variants, DeepSeek/GLM MLA models that
do not expose ordinary V tensors, Gemma’s heavy sliding-window structure, and
newer Qwen hybrids. On that basis, Claude revises the recommended cloud ladder
to use Mistral Small 3.2 as the second family and Llama-3.3-70B as the clean
scale anchor, with configuration verification before expensive runs.

Gemma becomes the key “not first, but maybe next” case. When the user asks
whether Gemma could be used, Claude says yes, but only as a different study, not
a clean replication. Its hybrid/sliding-window structure would mean many layers
never had full-history-conditioned values to preserve, so any comparison against
full-attention findings would be architecture-confounded. However, the new
profiling method makes this architecture difference scientifically useful rather
than merely disqualifying: in a hybrid model, the prediction is that the
graft-benefiting signal should concentrate on the sparse global-attention
layers. That would both support the mechanism story and suggest a practical
compression win, since only a subset of layers would need retained state. By the
end of the shard, Claude accepts the user’s broader intuition and adds Gemma 3
27B as a contingent, profile-first future stage if time and budget remain, after
Mistral and Llama.

Important terminology and framing emerging here:

- “profile-first” / “profile-then-graft” becomes the preferred transfer recipe.
- “graft-friendly layers” refers to layers with positive validation delta.
- “scale anchor” refers to Llama-3.3-70B.
- “clean replication” means models whose cache/attention architecture still
  matches the assumptions of ordinary ValueGraft surgery.
- MLA-style models are treated as the hard boundary because there is no ordinary
  V tensor to blend.

Handoff-relevant state at shard end: local Qwen work is complete and committed;
no jobs are left running; keys are staged but intentionally unused pending
explicit approval; the cloud plan now includes Mistral Small 3.2, Llama-3.3-70B,
transfer of the profile-derived procedure, and a contingent Gemma 3 27B
profile-first stage. The core scientific update from this slice is that the
project has moved from coarse global-alpha tuning toward a more mechanistic and
portable layer-profiled procedure, without claiming an unwarranted local
performance jump.

## Shard 3.

This shard covers two main threads: a `gpt-5.5` Codex discussion about
production/prior-art framing, and a long `claude-fable-5` overnight
execution/planning cycle that evolved from benchmark interpretation into a
heavily monitored multi-pod coding-agent program.

`gpt-5.5` clarified the external framing. It argued the current proxy result
should be described as a small but statistically reliable positive signal whose
magnitude is hard to map onto real coding impact because the proxy is
deliberately fragile and low-bandwidth. For production shape, it strongly
preferred a provider-owned opaque compaction handle over any client-managed raw
KV sidecar or fake prompt token; the clean mental model was “compaction-time
cache artifact,” short-lived and provider-scoped, not general latent memory. A
major correction then landed: modern hosted APIs are already closer to this
shape than previously assumed. OpenAI explicitly exposes compaction plus an
opaque encrypted carry-forward item; Anthropic exposes typed compaction blocks
and separately documents KV-based prompt caching; Gemini exposes adjacent
mechanisms like context caching and thought signatures but not the same clearly
documented general `/compact` primitive. `gpt-5.5` stressed careful evidence
levels: documented interface vs documented semantics vs inferred internals. This
triggered a new prior-art/product-surface investigation, with the uncomfortable
conclusion that frontier hosted APIs are much closer to the project’s proposed
opaque-compaction shape than earlier notes had acknowledged, though still
without direct evidence they are doing ValueGraft-style cached-value restoration
internally.

On terminology, `gpt-5.5` tightened the language: the precise object being
manipulated is “cached attention value vectors” or “per-layer, per-token,
per-KV-head value vectors stored in the KV cache.” “Activations” was judged too
broad, and “KV values” too vague. For ValueGraft specifically, “cached value
vectors” was presented as the cleanest term; for packed-summary approaches,
“cached key/value vectors for the summary tokens” is more accurate.

The much longer `claude-fable-5` section begins with extrapolation/tuning
discussion and gradually becomes an overnight operational log. Early on, Claude
described corrupted-value failure modes as semantic rather than syntactic:
fluent amnesia, confident denial, and donor-conversation bleed, with true
gibberish rare at 30B. It predicted corruption should stabilize over generation
by being overwritten with fresh self-consistent cache state, but stabilize onto
a possibly derailed narrative rather than recover true context. For a
friend-facing demo, Claude built a four-way Pokemon illustration contrasting
full context, deleted context, normal graft, and inverted graft; later the user
disagreed with treating that demo as evidence rather than illustration. That led
to an explicit correction: demos are not findings, demo artifacts were removed
from `results/`, and the rule “demos never live in the results tree or in
evidence lists” was recorded.

The overnight tuning discussion produced several important methodological
judgments. A 30B per-slot “posslots” mask looked surprisingly strong on holdout
(+0.038 nats, 10/10 wins versus +0.024 for the global-alpha incumbent), but the
user did not want it promoted to the main approach because it was too
validation-derived and messy; it was demoted to an exploration/secondary finding
pending contamination checks. The user proposed a factored parameterization with
one value per layer and one per head. Claude recognized this as a rank-1
decomposition idea and checked the actual 30B profile matrix. Result: head means
explain almost none of the variance, confirming “heads don’t matter” for this
Qwen family, but the matrix is not remotely rank-1; most slot-to-slot variation
is idiosyncratic/noisy, so the factorized approximation would mostly collapse
back to per-layer tuning and underperform the intriguing slot mask. Negative
coefficients were discussed seriously: the user intuited that correlated
directions may require negative weights, and Claude agreed the geometry is valid
in the linearized picture, but small-model experiments later showed clamped
factor fits beat signed ones in practice, suggesting variance/overfit dominated
any benefit from using negative coefficients there. A key evidence-grading rule
was made explicit: local / 4-bit / small-model results are for hypothesis
generation only, especially for nulls and boundary claims; 30B bf16 is where
claims are earned.

Another repeated theme was the distinction between “sense” and “facts.” Claude
kept emphasizing that the method restores contextual sense or framing more
readily than exact evicted facts; this became central when benchmark QA results
came in. LongMemEval stage 1 showed massive compaction damage (full context
around 52.5% accuracy versus compacted around 4–7%), but the various
intervention arms did not meaningfully separate on fact-retrieval QA. The honest
interpretation became: the benchmark is useful for quantifying damage and maybe
fabrication safety, but not for showing ValueGraft’s main advantage, because
when exact facts are gone, grafting cached values does not resurrect them. This
led to a major redesign: LongMemEval stage-1b and LoCoMo-as-planned were
criticized as expensive ways to re-ask a question already known to be near-null.
The salvage plan became a cheaper A/B-only standard-protocol mini-run for
citation purposes, while shifting emphasis toward continuation quality,
honesty/fabrication behavior, and end-to-end coding-agent tests. Later, stage-1b
hit an even harder limit: full-protocol A-mode LongMemEval haystacks (~110–120K
tokens) physically do not fit a bf16 30B on an 80 GB A100, so the
standard-protocol mini needed an H200. That failure path was eventually
recognized as a hardware boundary condition, not a software bug.

The honesty/fabrication line became one of the shard’s strongest surviving
findings. The user requested more behavioral/safety-oriented evidence, and
Claude ran a dedicated honesty suite at 30B bf16. This replicated the earlier
4-bit pattern: standard compaction fabricated confidently on decoy topics and
evicted facts, while the packed write-time-KV arms much more often either
answered correctly or admitted ignorance. By the end of the shard, Claude
described this as a full-precision replication of the “honesty effect” and one
of the write-up’s headline exhibits. Importantly, it also noted that value graft
itself did not appear to increase fabrication relative to plain compaction in
the LongMemEval QA setting.

Operationally, most of the shard is about scaling the overnight program across
pods, improving monitoring, and repeatedly correcting avoidable failure modes.
The user requested expanded parallelism, first from 4 pods toward 7–9, and
specified that the system should be resilient, auto-pulling results, waking the
agent on stalls, and not silently burning money. Claude gradually built or
claimed a hardened launcher, 5-minute pull plus 30-minute health checks, later
merged into one 5-minute loop with tiered checks, then strengthened again when
silent failures still occurred. A pre-commit size guard and clearer repo policy
were also added: docs/source/small JSON results are versioned; datasets,
weights, credentials, large binaries are not; a local pre-commit hook blocks
staged files over 4 MB. The user also specified that if Claude got stuck, it
should consult a different-model agent via CLI; this cross-model stuck protocol
was added to AGENTS-style guidance, with the note that Codex CLI
availability/pathing might need care.

Despite all the monitoring work, the shard records repeated operational misses.
Gemma exploration became a portability stress test with multiple integration
failures: dual RoPE bases, strict alternation rules in the chat template,
Qwen-specific assumptions hidden in shared helper code, and finally a deeper
hybrid-attention/sliding-window cache-shape failure. The first several failures
were template/plumbing issues that the user felt should have been caught locally
before burning pod time. Claude responded by instituting a stronger “full
context-construction dry run locally before renting GPU” rule, but later had to
refine that too: dry-running render output is not enough; the actual helper
functions used in execution must be called. Ultimately Gemma was killed as a
legitimate parked thread rather than an active overnight priority, with a
precise resume point: hybrid-attention-aware scoring/surgery is real new
machinery.

A major operational issue was monitoring and silent job deaths. Several
different jobs stalled or exited with too little visibility: stage-1b-mini runs,
honesty runs, shim transitions, and retriers. Claude kept patching the
monitoring stack: detect dead processes without completion markers, detect new
traceback/error lines, add syntax gates in the launcher, validate completion
counts, and remove blind exemptions for shim pods that “don’t write results.”
This sequence matters because the user explicitly called the lack of prompt
alerts “almost catastrophic” and asked for it to be recorded for handoff. There
is also a brief handoff experiment where the user wanted alternating
Claude/Codex shifts with sleep windows; Claude created a shift log and handoff
contract, and the transcript includes several “sleeping/waking” updates.

The highest-stakes science thread in the shard is the move into end-to-end
coding-agent evaluation. Initially Claude was not working on OpenHands quickly
enough, and the user flagged this, saying the coding track should have started
immediately once approved. Claude admitted it had let smaller unblocking tasks
preempt the main build and then focused on the shim. The resulting design used a
local OpenHands harness plus pod-hosted shims serving the 30B through an
OpenAI-compatible API. The shim itself handled compaction internally: OpenHands
always sent full histories, and the shim switched between A-mode (full context),
B-mode (same summary + tail compaction path as the experiment), and E-mode (same
plus cached-value blending). Early live logs confirmed compaction was really
firing and that E-mode recorded grafted-position counts. Later, a throughput
optimization was added: freeze the compaction boundary once compaction fires,
cache the summary plus snapshot keyed by the frozen prefix, and reuse it until
the tail regrows past threshold. This was intentionally not swapped mid-queue to
avoid mixing semantics within a comparison set; it was smoke-tested locally with
the expected `MISS, HIT, HIT` pattern before being staged for later deployment.

The coding track itself evolved from a small E1 pilot toward a larger matrix.
First signals were encouraging: an initial B-vs-E round produced B failing both
tasks and E passing both, which Claude correctly treated as promising but still
tiny-n. The user repeatedly requested creativity and more “spark,” not just
systematic matrix work, so Claude added anti-graft (`alpha < 0`), shuffled-graft
controls, dissociation probes (“can the agent state the exact constraint?”),
threshold sweeps, wildcard pods, and later a tuning ladder for coding-agent
arms: B, single-alpha E, coarse per-layer E, and the slot-mask challenger. The
user also specified a champion/challenger discipline with holdouts and later
confirm/final phases. Claude eventually formalized a three-phase agent-eval
pipeline: explore on early seeds, confirm side-by-side on fresh tasks, then a
sealed final eval on genuinely held-out seeds and/or freshly authored tasks.

By late in the shard, the coding-agent overnight program had become a large
matrix across up to 7 pods, with several dozen to roughly a hundred objective
runs through real task harnesses scored by `pytest`. However, the most important
late correction is a contamination disaster: after the night’s coding results
accumulated, Claude discovered that the shim had been built under an original
one-task-per-pod assumption, so when multiple tasks/modes shared a pod,
server-side session state could leak across arms. The user classified this as a
serious waste of time and money and required that it be fixed and redone
correctly. Claude acknowledged this was a simple unchecked assumption surviving
a scale-up, quantified that the contamination scope was not necessarily total
but serious enough to undermine trust, and recommended spending modest extra
compute on a clean post-fix rerun rather than trying to salvage the tainted
dataset argumentatively. This is one of the key handoff points: many of the
coding-matrix results from that overnight run are suspect because of
session-state leakage across arms on shared shims.

Several concrete result statuses are important for later reconstruction. The
57-slot mask, exciting on continuation-style metrics, ultimately failed its
wrong-conversation contamination guard in the coding-agent context and was
declared dead “as a finding” rather than promoted. The per-layer tuned
coding-agent configuration emerged as the current champion candidate and, unlike
the slot mask, was described as passing its contamination guard. There was also
an unresolved or newly investigated anomaly around global `alpha = 0.75`
underperforming neighboring alpha values in the coding-agent table; Claude
suspected the same session-sharing bug could explain it and began
isolated-session reruns to test that. Another late lesson was that some coding
tasks were too easy: plain compaction reportedly passed around 90% on
single-constraint tasks because constraints survived summaries, so harder
multi-constraint tasks would be needed for a meaningful champion-vs-baseline
demonstration.

Throughout the shard, the user required that everything important be captured in
state documents for cold-start handoff. Claude repeatedly claimed to update
STATE/DECISIONS/other notes to reflect current board state, rules, failures, and
new plans; whether that happened correctly is outside this shard, but the
conversational intention is strong. The user also established a dual-agent
convention: another agent may read the repo and very occasionally create new
non-conflicting files/folders and even commit them, but should not modify
existing files; therefore Claude should avoid `git add -A` style staging and
treat unexpected new files as normal. Late in the shard, the user explicitly
asked for impeccable handoff logging and alternating shifts between agents,
reinforcing the need for summary artifacts like this one.

Overall, the mainline story is: prior-art framing was corrected toward “hosted
APIs are already much closer to opaque compaction handles than we thought”;
value graft continued to look more about semantic continuity/sense than exact
fact retrieval; LongMemEval QA was partially demoted as an arm-separation test;
the honesty/fabrication effect strengthened and replicated at full precision;
end-to-end coding-agent evaluation finally started and produced tantalizing
positive signals plus a broader tuning/champion framework; but a serious
session-state contamination bug tainted much of the shared-shim coding matrix
and forced a redo mentality. The shard ends with the user rejecting the
contaminated tranche and requiring Claude to fix it and redo it correctly.

## Shard 4.

This shard captures a long corrective phase in which `claude-fable-5` repeatedly
tightened the agent-evaluation pipeline after contamination, monitoring, and
instrument-design failures, while the user prioritized real coding-task results
and durable documentation.

### Mainline trajectory

- The session began with a “do it right” reset around a **150-run clean
  re-run**: fresh seeds, disjoint task assignment, probe-gated lanes, and
  pre-registered analysis. A new synthetic task `t3` was introduced specifically
  because earlier tasks ceilinged and summaries could carry too much.
- Very early, `claude-fable-5` reported that the apparent **`E@0.75` anomaly**
  likely was not real. Clean rows began to suggest the old anomaly came from
  serving/instrumentation bugs, not a true behavioral reversal.
- The user requested faster movement and for everything that had gone wrong to
  be documented. This led to a durable repo-level record structure:
  **`INCIDENTS.md` for failures, `STATE.md` for live status, `DECISIONS.md` for
  methodology, and later `HANDOFF.md` for replacement-agent continuity**.

### Instrument / methodology corrections

- A major new gate was added: **instrument sensitivity must be checked before
  trusting agent runs**. Rule: if baseline Compacted/B performs too well, abort
  and redesign harder tasks; if B performs poorly enough, proceed.
- The project explicitly separated:
  - **clean/banked** results: stage 1 damage quantification, stage 2 real-trace
    recovery, honesty replication, TF/tuning/guard work
  - **suspect or void** agent results: night matrix arm comparisons, broken
    probe runs, dissociation probe rows, artifact rows from infra failures
- A strong repo rule emerged: **every scored result must be versioned in
  `results/`**, with contaminated or superseded rows preserved under
  `_QUARANTINE_` paths rather than left in scratch space or deleted.
- The agent repeatedly emphasized that all future analysis should read the repo
  directories, not scratchpad outputs.

### Interpretation of the science during this shard

- `claude-fable-5` expressed high confidence that the **honesty result** was the
  strongest, cleanest finding: compaction caused fabricated confidence on
  never-discussed topics, whereas write-time-KV methods preserved “knowing that
  one doesn’t know.”
- The continuation-recovery effect was treated as **real but modest and
  conditional**.
- For live coding agents, `claude-fable-5` advanced a recurring interpretation:
  **grafts may recover “sense” / feeling-of-knowing more than exact facts**.
  This could help agents by making them re-check the right files even if they
  cannot directly recite lost numbers. This became an explicit hypothesis to
  test via compliance-vs-recall dissociation.

### Tuning / arm framing decisions

- Head-level and slot-level tuning were effectively demoted. The surviving tuned
  candidate was **per-layer value grafting**.
- The in-flight five-arm comparison became:
  - `Original`
  - `Compacted`
  - `Compacted + value graft (α=0.75)`
  - `Compacted + value graft (α=1.0)`
  - `Compacted + layer-tuned value graft`
- The old internal letter labels (`A/B/E`) were judged too opaque for
  human-facing use; canonical human-readable names were adopted for writeup and
  reporting.

  - forgot earlier promises to test
  - rediscovered the same facts repeatedly
  - declared completion without verification

- Another major methodological bug surfaced late in the shard: the baseline
  Compacted arm had inherited a **deliberately detail-poor summary prompt** from
  mechanism experiments.

  meaning the baseline summary was effectively **adversarially bad by design**,
  not representative of real production summarization.
- This was recognized as a serious inherited-parameter mistake: a
  mechanism-experiment setting had silently crossed into the live-evaluation
  instrument.
- The project then switched to a **production-faithful, more specific
  summarization prompt** and treated the prior summary regime as
  invalid/confounded for realistic live-task claims.

### Final “humane” / production-calibrated regime

- The corrected real-task compaction regime became:
  - **12,000-token trigger**
  - **6,000-token retained tail**
  - **production-faithful summary prompt**
  - expected **2–6 recompactions** per episode
- “Humane” was acknowledged as an internal, loaded nickname; for external
  writing it should be translated to something like **production-calibrated
  compaction**.
- Summary length remained on the short side (~500–650 tokens against a 6K tail),
  but was considered within convention; it was logged as a **future sensitivity
  knob**, especially for long episodes where compression ratios become extreme.

### Important semantic / mechanistic clarifications

- The user asked a precise question about where graft source values come from.
  `claude-fable-5` clarified:
  - **source values come from the tail in its original natural position in the
    full pre-compaction context**
  - there is **no second copy** of the tail created and re-encoded as a source
  - summary-token source values come from the summary as generated at the end of
    the full context
- This matters because it ties the intervention directly to **state written
  while the full context still existed**.

### New endpoints and analytic enrichments

- The project expanded beyond binary success/failure to capture:
  - step counts
  - token/compaction traces
  - wall-clock timing
  - recall probe outputs
  - `self_terminated` vs `timed_out`
- These became explicit **secondary endpoints**, especially useful if tasks
  floor or ceiling.
- A new qualitative/behavioral metric also emerged from autopsy work:
  **promise-keeping** (whether the agent later executes early commitments it
  made to itself). This was proposed as a direct behavioral probe of context
  integrity.

### Open questions / unresolved state at shard end

- Whether real standard tasks are **too hard**, **too easy**, or well-calibrated
  remained unresolved, though compaction pressure itself was clearly present.
- The key ceiling datum the project was waiting for was **Original-arm
  performance on real tasks**, especially seaborn and flask-style issues.
- The live system was described as handoff-ready, with `HANDOFF.md` meant to let
  a fresh agent recover the true state more reliably than the degraded
  long-context agent could from memory.
- `claude-fable-5` explicitly framed its own degradation as **long-context /
  repeated-compaction degradation**, paralleling the very phenomenon being
  studied.

### Handoff-relevant bottom line

- By the end of the shard, the project had abandoned the earlier “tier-0”
  real-task regime and was running a **production-calibrated real-task
  evaluation** on standard SWE-bench-style issues with:
  - corrected summary prompt
  - larger retained tail
  - calibrated compaction frequency
  - quarantined old rows
  - result provenance and richer metadata
- The biggest substantive lessons were:
  - many earlier live-agent rows were confounded by **instrument design**, not

  - **baseline quality matters as much as intervention quality**
  - inherited defaults from mechanism work can silently invalidate behavioral

  chain-task success directly.

- A long technical discussion then developed around **how J-lens might integrate
  into the current ValueGraft pipeline at minimal cost**. `codex`’s bottom line
  was:
  - **Applying** an already fitted J-lens can be cheap enough if sampling is
    narrow.
  - **Fitting** a lens is the expensive, model-specific part because it requires
    backward passes.
  - J-lens does **not** directly read the KV cache; it reads **residual stream
    activations**, which are the per-token/per-layer hidden vectors from which
    attention projections are derived.
  - Keys and values were explained as learned linear projections of the residual
    stream (`W_K`, `W_V`), not “decodings” in the usual sense. The KV cache
    stores these projections for past tokens so generation can reuse them.
    ValueGraft’s intervention therefore blends cached K/V that were produced in
    richer prior context.
  - J-lens instead reads the downstream effect: after compacted or grafted K/V
    influence attention for a new token, does the resulting residual stream
    recover the concept that was present in the original full-context state?

- The user pressed for a clearer conceptual model, and `codex` distinguished
  three things:
  - the **residual stream** as the full hidden state vector at a layer/token,
  - the **J-space** as a meaningful subspace/direction family inside that
    residual stream associated with verbalizable content,
  - the **J-lens** as the readout that maps residual activations into
    vocabulary-token scores. This corrected an earlier blur between “sampling
    activations generally” and “reading a specific concept-bearing subspace.”

- On output volume and cost, `codex` explained that J-lens can emit anything
  from tiny top-k readouts to absurdly large full-vocabulary dumps. Full
  exhaustive readout across all generated tokens, all layers, and the whole
  vocabulary was judged impractical as routine telemetry, both for storage and
  compute. The recommended shape was **rare sampled telemetry**: top-k or
  targeted concept scores at a few diagnostic points.

- The user then proposed a concrete sampling regime around the compaction
  boundary only: before summary, after write-time summary, after fresh
  re-encoded summary, and after grafted summary. `codex` endorsed this with an
  important correction: in the grafted condition, the informative readout is
  **not “inside the grafted summary tokens”** (those are cached past tokens),
  but on a **subsequent token that attends to the grafted cache**. The resulting
  minimal four-state design was:
  1. Full old context before/around summary.
  2. Summary tokens as originally generated in old context.
  3. Fresh compacted context with re-encoded summary.
  4. Grafted compacted context, then one diagnostic continuation/probe token
     after grafted K/V has had an effect.

- `codex` said it could likely figure out how to do this, but recommended an
  **offline diagnostic script first**, not live shim instrumentation. Proposed
  workflow: load model/tokenizer, load or fit a J-lens, reconstruct one
  compaction event, build the four states above, hook selected residual layers,
  run J-lens, and save top-k readouts as JSON. This was framed as a crisp,
  narrow mechanistic snapshot rather than broad instrumentation.

- Model-choice implications were discussed. `codex` argued that `Qwen3.6-27B` is
  attractive for a next phase because it is stronger behaviorally and has a
  pre-fitted J-lens path in Anthropic’s walkthrough, but it is **not a drop-in
  replacement** for the current subject model. Reasons given:
  - current subject model uses the existing KV-cache surgery assumptions;
  - Qwen3.6-27B has a **hybrid DeltaNet/attention architecture**, so the
    retained-state story is different and ValueGraft would need reframing;
  - Qwen3.6’s explicit “preserve thinking” feature is scientifically relevant
    but also a confound that would need its own condition. So Qwen3.6 was
    treated as a plausible future subject, not a simple migration target for the
    current run.

- The cost asymmetry for J-lens remained a key conclusion: **fit once =
  expensive; apply many times = relatively cheap if sampled narrowly**. Because
  a pre-fitted lens did not appear to exist for the exact current

  explicit claim: the lens is a **low-resolution aggregate corroborator**, not a
  dramatic single-case explainer.

Paper-writing decisions and corrections:

- The first synthesis draft was long and repetitive; critics said it restated
  the convergence story too many times, let the lens take over too much space,
  and had confusing seams around model identity and 4B claims.
- The most important correction concerned **referent**. An accuracy critic noted
  the draft’s “grafting does not recover omitted facts” line contradicted its

  scale-dependent or architecture-dependent. Final framing became:
  - sense/stance dissociation **replicates across both tested models**;
  - referent recovery is **present on 30B but does not replicate on 27B**;
  - cause remains open.
- Fable was made a hard requirement in two roles, because the main loop kept

  - **conceptual gut-checks** on claims/framing before they hardened;

Operational/pipeline notes:

- Pod cost discipline mattered throughout: terminate idle pods, do

- The 27B/30B paper-support jobs ran sequentially to avoid OOM.

  - secure A100 capacity failures on RunPod;
  - community-cloud fallback missing `rsync`;
  - a `torch`/`torchvision` mismatch;
  - a more serious silent CPU fallback caused by installing CUDA-13 torch on a

  - verify `torch.cuda.is_available()` on new pods before trusting runs;

  - later, monitor notifications were redesigned to **debounce with backoff**

K/V exploration:

- The novel technical core was **key grafting with RoPE re-rotation**. This was
  validated to fp32 precision: re-rotated write-time keys matched freshly
  encoded keys at new positions nearly exactly. This established that K-grafting
  was technically sound enough to test.
- The first 30B sweep was explicitly **coarse and untuned**: global uniform
  `alpha_K` / `alpha_V` policies, no layer/head tuning yet. The user asked about
  this, and the answer was that tuning machinery existed but the current run was
  meant as a cheap “do keys matter at all?” screen.
- Coarse 30B result: **V-only reproduced the known positive referent effect**,
  so the sanity gate passed; however **K-only hurt everywhere**, and
  coupled/independent policies did not clearly beat V-only. Honest conclusion:
  **value is the operative axis; uniform key grafting does not help**.
- This did not end the question immediately. Because the user had asked about
  tuning, a **per-layer key probe** was launched to test whether uniform

- Per-layer work was described as the likely final closure of Phase 2: if no

- Later summary material in this shard indicates the eventual landing was still

Lens / interpretability evolution:

- The user asked whether the lenses had faded from the project too much and
  suggested pushing farther forward in the conversation to a more visible
  inflection point.
- This triggered a major methodological realization: **teacher forcing
  suppresses divergence**. If all arms are forced down the same token path,
  internal differences are flattened. That led to a new idea: free-generate from
  the boundary and inspect the first fork where trajectories diverge.
- The first free-divergence idea was then tightened by Fable. Fable caught
  several dangers:
  - greedy decoding can turn a tiny 51/49 preference into a dramatic-looking
    fork (**decoder amplification artifact**);
  - a single vivid case would create rhetorical over-weight (**availability
    leak**);
  - calling nulls “subtle” risks a heads-I-win interpretation.
- The corrected design added:
  - fork margins;
  - decoding robustness across temperatures;
  - an all-case distribution instead of a hero anecdote;
  - a pre-registered **DISCONFIRMING** bucket.
- The free-divergence runner was expanded to a 43-case distribution. Later
  summary text in this shard says it found **0/43 clean toward-A forks**, which
  strengthened the existing paper claim rather than overturning it: even the
  sharper method did not produce a vivid internal-fork exhibit.
- After the user said the **lens trajectory** direction seemed more promising
  than more key work, the discussion shifted again. Fable then argued that
  chasing a vivid trajectory plot was probably the wrong goal. Its better
  reframe was: **bound the subtle effect rigorously instead of trying to make it
  look vivid**.
- That new lens-bounding design:
  - drops free-generation contamination;
  - teacher-forces A/B/E on the same gold continuation window;
  - measures mean `(logprob_E - logprob_B)` lift;
  - compares the true graft to a **placebo/random graft**;
  - uses bootstrap CIs and a pre-registered null.
- The user approved this with “Go go go,” and the build + pod provisioning for
  that bounded lens experiment began at the end of the shard.

## Shard 12.

This shard covers a major strategic pivot: the project refocused away from the
lens material and back onto value grafting as the primary contribution. The user
repeatedly emphasized that the paper and future experimentation should
foreground grafting benefit across more scenarios, with the lens treated as
secondary because its payoff had turned out small. That led to a Phase 4 plan
combining new experiments with more mined examples from existing data, plus
explicit guidance that Fable should be briefed on this focus rather than
offering direction-agnostic edits. Terminology was also flagged: “lens” had
become overloaded across logit lens, tuned lens, and J-lens, with many ambiguous
bare uses. This was accepted as a real paper flaw and added as a new
“terminology consistency” review dimension.

There was a repo/documentation cleanup phase. Obsolete markdown files were moved
under `docs/` using the repo’s date-hour prefix convention derived from first
commit history; `README.md` became a published snapshot copied from `REPORT.md`;
top-level tracking files (`STATE`, `DECISIONS`, `INCIDENTS`, etc.) were
repeatedly refreshed; and new process rules were recorded, including unique
output filenames per run (`<experiment>_<model>_<run-id>.json`), explicit launch
logging of model/output path, verification that the correct model actually
loaded, final multi-angle Fable passes, and later an idle-pod watchdog.

The assistant initially pursued a placebo-style “effect-bound” experiment. On
27B, the result looked like: aligned graft decisively beat random-value placebo
(content-specific effect) but did not clearly beat plain compaction. A supposed
30B rerun was later discovered to have accidentally rerun 27B because the script
ignored the environment override and only respected `--model`; it also wrote to
the default path and overwrote the prior output, which motivated the
output-naming rule. A correct 30B rerun then produced alarming results: on a
short window and then full continuation, graft looked null or negative against
compaction, apparently challenging the paper’s primary claim.

That apparent crisis triggered a deep audit. The assistant first hypothesized
preamble-only measurement issues, then a genuine failure of the primary effect,
then champion-tuning differences, then case-set differences, but each of those
explanations was weakened or ruled out. The key recovery came after the user
requested Fable’s help. Fable’s diagnosis was that the effect itself was stable
but the estimator was broken: the project had been using the mean of the ratio
`(E-B)/(A-B)`, which becomes unstable with small denominators and can produce
large misleading swings. Recomputing saved and live runs on robust metrics
showed that referent and sense consistently improved on raw `E-B`, median ratio,
and `% helped`, while stance stayed near zero; the dramatic mean-ratio numbers,
especially the famous strong negative stance values, were artifacts. The live
reruns also showed determinism within a fixed environment; earlier apparent
instability came from environment drift plus the bad estimator, not random
nondeterminism.

This led to a major methodological correction. The robust standard became raw
`E-B`, `% helped`, and bootstrap confidence intervals, with mean-ratio retired
or heavily caveated. Bootstrapped CIs on existing data gave a more nuanced
picture: referent was significant on the logprob metric, sense was positive but
underpowered, and stance was null. The judged headline metric from the paper was
recognized as separate and load-bearing, but its CI audit was deferred because
its data structure was more complex. The effect-bound probe itself was demoted
from apparatus-of-record because it used different teacher-forcing code and had
been the vehicle that exposed the estimator problem.

The estimator audit spread further. The user asked whether prior per-layer
negative results and key-graft harms might also be suspect. Recomputing K/V
results on raw `E-B` showed that value graft remained real, but keys were
basically neutral rather than dramatically harmful. The scientific conclusion
“value is the operative axis; keys don’t help” was kept as settled and
explicitly closed; only the wording of the paper needed correction from “keys
hurt” to “keys are inert/neutral.”

Another thread concerned architecture breadth. The user wanted the work extended
across more model families and nudged the assistant to avoid stale model
choices. The assistant researched newer mid-2026 open models, noted that
MLA-based models like DeepSeek/Kimi are principled exclusions because they do
not expose per-head values in the needed way, and scoped a cross-architecture
map across Qwen, Gemma, Mistral, GLM, OLMo, etc. Fable contributed a useful
design critique here too: fixed summaries control one confound but can create
another if they are unrealistically strong or if cross-model comparisons are
contaminated by differing baseline compaction gaps. That discussion led to using
neutral Sonnet-generated fixed summaries, positive-direction smoke gates, and
later the idea that champion-tuning profiles across architectures could become
an interesting “architectural fingerprint” extension.

The sweep implementation itself turned into a second major debugging storyline.
The assistant built a cross-architecture harness, added smoke checks, per-model
validation, and later an idle-pod watchdog. There were repeated operational
issues on pods: missing `rsync`, hidden deploy failures due to suppressed
stderr, a community pod dying after disk filled, need for 400G pods, and
eventually two pods in parallel. More importantly, the assistant discovered that
“UNSUPPORTED” should be reserved for machinery failures, not for models with
negative graft effects; the map should record positive, null, and negative
outcomes, not discard negatives.

The most revealing model result in the shard was Qwen2.5-32B. The cross-arch
harness reported a strongly negative graft effect. The assistant first suspected
the fixed-summary design, then worried aloud about “token matching,” which
prompted the user to note that the project had long since abandoned sloppy
token-matching approaches. After reading the code carefully, the assistant
corrected that misdescription: the alignment logic was actually matching the
summary span to itself and the tail to itself, not doing arbitrary
conversation-token matching. The user still disagreed with using fragile
overkill if the operation should just be a direct span/substring map.
Investigation showed that on the tested cases the fuzzy alignment dropped zero
tokens and gave perfect one-to-one pairs, so it was not the cause of the Qwen2.5
failure. The user’s engineering instinct was still accepted, though: the code
was simplified from difflib-based matching to a direct span-offset map, loudly
raising on divergence instead of silently degrading. Equivalence was verified
across all 12 conversations before switching, so no existing results changed.

To determine whether Qwen2.5’s negative effect was architecture or harness bug,
the assistant ran several isolations: fixed-summary and self-generated-summary
variants in the cross-arch harness, then the trusted original
`gap_closure_cat.py` on Qwen2.5 itself. All agreed that Qwen2.5’s graft effect
was significantly negative. That established a striking mechanistic finding: the
same value graft that helps on Qwen3-30B reverses on Qwen2.5-dense. The
assistant and user treated this not as a reason to give up but as a valuable
architecture-sensitive result and a sign that the mechanism is real rather than
generic.

However, the next positive-control check complicated the sweep again. Running
the cross-arch harness on the known-positive Qwen3-30B with the fixed Sonnet
summaries failed to reproduce the known positive F1 result, coming back
null-to-negative. That meant the harness was not yet validated as a replacement
for the original apparatus on positive cases. The leading hypothesis became that
the fixed-summary design itself suppresses the effect: value grafting may depend
on the model’s own generated summary/write-time state, not merely on reading a
foreign summary text. A new decisive isolation was launched: Qwen3-30B through
the cross-arch harness using self-generated summaries. At the same time, Gemma
work exposed a separate harness bug: Gemma’s strict chat-template alternation
broke summary-snapshot construction, so a Gemma-specific fix was developed
locally. There was also a note that even after the template fix, Gemma’s
HybridCache/sliding-window structure might prove to be a real architectural
boundary rather than a software bug.

By the end of the shard, several conclusions were stable and several were still
live:

- Stable:
  - The paper had been overweighting lens analysis; grafting should be the
    center.
  - “Lens” terminology needed explicit disambiguation.
  - The mean-ratio estimator was broken for reporting and had to be replaced by
    raw `E-B`, `% helped`, and bootstrap CIs.
  - The primary grafting effect is real on robust metrics, but more nuanced than
    earlier point estimates suggested: referent strongest/significant, sense
    positive but underpowered, stance null.
  - Keys are closed/settled: they do not help; dramatic “keys hurt” claims were
    estimator artifacts.
  - Qwen2.5 is a genuine negative-transfer architecture under the trusted
    apparatus.

- Live / unresolved:
  - Whether the cross-architecture harness can reproduce the known positive
    Qwen3 result when using self-generated summaries.
  - Whether fixed summaries are fundamentally the wrong design for cross-arch
    comparison because they suppress the mechanism.
  - Gemma-specific support: a template bug was fixed, but the true
    sliding-window/HybridCache boundary remained to be tested.
  - The judged headline metric still needed its own CI audit.
  - A future public-facing repro path was emerging as a concrete need: one clean
    command, pinned models/data, minimal README section, and repo disclaimer.

Handoff-relevant context: the assistant repeatedly updated `STATE.md`,
`DECISIONS.md`, `INCIDENTS.md`, `FINDINGS.md`, and task tracking to preserve
this arc; introduced pod/process rules like disk checks, unique output naming,
model verification, and idle watchdogs; and treated Fable as essential for both
scientific diagnosis and paper framing. The major conceptual shift of this shard
is that the project moved from “possible replication crisis” to “effect
survives; estimator/reporting were wrong,” while simultaneously uncovering a
more interesting mechanistic landscape: value grafting appears
architecture-sensitive enough to help on some models and reverse on others.

## Shard 13.

This shard centered on a cross-architecture validation scare that turned into a
stronger mechanistic claim. The team had already planned a future `reproduce.py`
entry point that would wrap trusted probes behind filterable flags
(`--experiment`, `--model`, `--metric`) and skip outputs that already exist, so
the same interface could later reproduce the full paper exactly without
rerunning everything now. Claude noted this should target the final corrected
science, not transient numbers.

The main scientific issue was a failed positive control in the cross-arch
harness when using a fixed Sonnet-written summary. Claude treated this as
important enough to record in durable memory/FINDINGS and ran an isolation test
on Qwen3-30B with a self-generated summary. The user emphasized preserving these
lessons. A key interpretation emerged before the result landed: if self-gen
restored the known positive while fixed-summary stayed null, the implication
would be that ValueGraft depends on the model’s own act of summarization rather
than arbitrary compressed text, which would both fix the methodology and deepen
the paper’s mechanism story.

They worked through the confound from self-generated summaries being more or
less detailed. The user realized gap-based reasoning partly protects against
this; Claude refined that point: the normalized ratio is conceptually gap-robust
but had already been retired as unstable, while the new primary metric `E-B` is
stable but not gap-normalized. The proposed reporting fix was to keep raw `E-B`
as primary, report pre-graft gap `A-B` per model, add a conditioned ratio only
where the denominator is large enough, and log summary token counts so
summary-detail variation is visible rather than hidden.

Another operational issue was poor progress visibility. Claude found that the
cross-arch harness only emitted `RUN` and `WROTE`, unlike `gap_closure_cat`, so
in-flight runs looked opaque except for GPU utilization. Claude then patched and
deployed per-conversation progress logging (`[progress] conv X/12`) for future
runs, with the intention that watchers remain quiet unless a run finishes or
errors, while manual checks can recover rough ETA.

The decisive correction arrived later in the shard: the Qwen3-30B
self-generated-summary isolation run came back strongly positive (reported as
referent `+0.136`, CI positive, 81% helped; sense also positive), closely
matching the trusted earlier result. Claude treated this as confirmation of
three points: the harness itself was valid, the fixed foreign summary had been
suppressing the graft, and the mechanism likely requires the model’s own
generated summary. This reframed the episode from a possible harness bug into a
mechanistic finding plus a concrete sweep change: rerun the cross-architecture
sweep with self-generated summaries.

Model-level status and sweep planning were also updated. Mistral’s fixed-summary
run was now considered biased and in need of a self-gen rerun if the isolation
succeeded. Claude then started scaling out to multiple pods because total
compute cost would be roughly unchanged while wall-clock time would fall, with
idle-watchdog protection to prevent waste. Proposed/active model coverage
included modern dense, MoE, sliding-window, and other architectures, plus the
idea of adding older models for a generation comparison. Claude specifically
highlighted Mixtral-8x7B as the most informative older MoE and Llama 2 /
Llama-2-13B as the notable older dense family, with the caveat that Llama 2 had
no near-30B release so scale would be mismatched.

There was also an important process update for paper review. The user required
that every major shareable revision receive one Codex review using GPT-5.5 at
extra-high reasoning effort, but only once per major revision because it is
expensive. Claude first misunderstood this as something the user might need to
run externally, then corrected course after the user explicitly said Claude
should run it. Claude investigated the local environment, discovered the Codex
CLI was not on PATH, installed it, verified it was already authenticated through
the user’s ChatGPT login, and confirmed that the existing config already
defaulted to `gpt-5.5` with `xhigh` effort. The agreed invocation for later
review was `codex exec -s read-only ...`, and Claude said AGENTS.md would be
corrected to reflect that Claude, not the user, performs this pass.

Terminology and reporting context worth carrying forward: the team was already
in the middle of broader corrections including the shift from mean-ratio to raw
`E-B` plus CIs, the reframing that keys are neutral rather than harmful, and the
emerging “own-summary” mechanism. Claude repeatedly framed the fixed-summary
failure as evidence that negative agreement alone was not enough validation; a
positive control was essential and in this case uncovered the deeper story. By
the end of the shard, the sweep was moving onto self-generated summaries with
more pods, better progress logging, explicit cost/runway tracking, and a richer
mechanistic narrative rather than a simple generalization result.
