> the structural/experimental methodology — above all, **who or what generated each piece
> of data**. That omission is not a stylistic gap; it is the difference between a

> model's own or written elsewhere — it turned out to determine whether the effect even

## 1. DATA PROVENANCE — for EVERY token in the experiment, state WHO/WHAT produced it
This is the section that was missing and matters most. For each conversation, document the
origin and exact generation procedure of each component:

- **System prompt** — authored by us? templated? give it.
- **User turns / prompts** — AUTHORED by us (the experimenters), not model-generated. Say so explicitly and say WHY (real user prompts aren't model-generated; a result that depended on model-generated prompts would be invalid).
- **The planted manipulation** (referent/sense/stance/ruled_out/evicted_fact/strong_prior facts) — authored; how; the categories; how many; the design.
- **Assistant replies (the conversation body)** — GENERATED IN-CONTEXT BY THE TEST MODEL ITSELF (per-model-native design). State: this is native per model, why that matters (the graft re-injects the model's own write-time values, so context must be what the model itself would produce), the exact generation config (greedy vs temperature, max reply length, seed, cache handling). **If any replies were generated by a DIFFERENT model, that must be stated loudly** — it is the difference between valid and invalid, as we learned.
- **The compaction summary** — SELF-GENERATED by the test model (the model summarizes its own conversation). State the summary prompt, the generation config, and the prior finding that a FOREIGN summary suppresses the effect (so self-gen is required, and it matches reality).
- **The gold continuation** (the teacher-forced target the metric scores) — derived from the PLANTED FACTS, SHARED across models, NOT model-generated. State why (the difference metric cancels target-nativeness only if the target is shared).

## 2. PROCEDURES — exact, reproducible
- **Compaction / B-context construction**: exactly how the compacted context is built (system + summary-as-assistant-note + tail), per template family.
- **The graft**: write-time KV snapshot, which vectors (VALUES; keys neutral), alpha, the alignment method (difflib positional-within-region — and the history: a strict variant was tried and reverted because it breaks on thinking-model self-gen).
- **The metric**: raw_EB = lp_E − lp_B, teacher-forced on the shared gold; the robust estimator (raw E−B + bootstrap CIs, NOT the retired mean-of-ratio); per-conversation cluster bootstrap; the categories.
- **Gates/exclusions** (design v2.1): per-model HEADROOM (A−B gap) normalization + threshold; TASK-COMPETENCE (lp_A) inclusion; floor handling (no gap = uninterpretable, NOT "harm"). State every exclusion rule and how many were excluded.

## 3. MODELS — EXACT checkpoint ids, no ambiguity
- Give the FULL HF repo id of every model (e.g. `Qwen/Qwen3-30B-A3B-Instruct-2507`, NOT "Qwen3-30B"). - Per-model: the attention-geometry hyperparameters used as predictors (n_kv_heads, head_dim, GQA ratio, QK-norm presence, RoPE theta, layers), read from config, reported in a table.

## 4. DESIGN RATIONALE / SCOPE CONDITIONS — document the WHY, not just the WHAT
- The per-model-native (matched-scaffold) design and WHY (nativeness is part of the mechanism; each model measured on conversations it would actually produce). This is a scope condition and a finding, not a footnote.
- The pre-registered geometry hypothesis + that it was pre-registered before the 16-run.
- The two within-vendor dense/MoE de-confound pairs and why they carry primary inferential weight.

## 5. REPRODUCIBILITY
- Seeds, determinism, the single filterable entry point, exact model ids, exact data (or its generation procedure). A reader with a GPU must be able to reproduce every number.
